# 開發、測試與 clasp

一般安裝直接用 [瀏覽器步驟](部署指南.md)。本文件供要修改程式的學生使用。

## 本機準備

Node.js 22 以上、Git；本專案沒有 npm 套件相依。

```sh
git clone https://github.com/canlgz/ResumeRAGbot.git
cd ResumeRAGbot
npm ci
npm run check
npm test
npm run bundle
npm run check:bundle
npm run check:docs
```

`check` 檢查 GAS 語法與 manifest，`test` 包含直接執行單檔的學生全流程模擬，`check:bundle` 確認單檔、分檔及 START_HERE.html 一致，`check:docs` 檢查文件相對連結及範例一致性。它們不使用真實金鑰，也不能驗證帳號權限或實際模型品質。

## 程式結構

| 檔案 | 職責 |
| --- | --- |
| `gas/Config.gs` | 指令碼屬性、設定驗證及安全錯誤碼 |
| `gas/StarterResume.gs` | 首次初始化建立學生自己的示範文件 |
| `gas/Knowledge.gs` | 公開文字擷取、切段、索引、同步與排序 |
| `gas/QuickTopics.gs` | 同步分類代表主題、完整互斥來源分配及執行中的選單 |
| `gas/PortfolioStore.gs` | 私有校對、確認、公開副本登錄與限時管理憑證 |
| `gas/Portfolio.gs` | 作品副本分享／撤回、匿名圖片檢查與 LINE Flex 卡片 |
| `gas/Conversation.gs` | 使用者隔離的短期指向與追問記憶 |
| `gas/Chat.gs` | 作品／主題問答、追問與卡片訊息組合 |
| `gas/Review.gs`、`gas/ReviewUi.gs` | 限時主人校對 RPC、內嵌管理頁 |
| `gas/Images.gs` | 圖片位置讀取、內容雜湊、同步 OCR 與私有索引快取 |
| `gas/Gemini.gs` | 向量／生成請求、來源驗證與錯誤分類 |
| `gas/Feedback.gs` | 將未回答問題寫回同一份文件的維護區 |
| `gas/Line.gs` | 首頁、快速回覆、載入動畫與 Reply API |
| `gas/Webhook.gs` | 秘密入口、LINE 事件處理與去重 |
| `gas/Admin.gs` | 初始化、設定檢查、同步管理及 Webhook 網址 |
| `gas/appsscript.json` | 執行環境、OAuth 權限與 Web App 設定 |

來源只讀選定分頁中 PUBLIC 區塊的正文與圖片，待補充區與 PRIVATE 區塊排除。圖片 OCR 只在同步執行，問答時僅讀原文及圖片雜湊檢查新鮮度；結果與快取存於私人 Drive 索引 JSON。所有事件仍同步處理；沒有訊息佇列或自動 Push 重試。

## 使用 clasp 上傳到自己的專案

以下命令以 clasp 3.3.0 的指令介面為基準。本機 Node.js 版本仍依本專案要求使用 22 以上。

1. 安裝並登入：

```sh
npm install -g @google/clasp@3.3.0
clasp login
```

2. 到 [Apps Script 使用者設定](https://script.google.com/home/usersettings) 開啟 **Google Apps Script API**。這只供命令列操作，瀏覽器安裝不需要。[Google clasp 說明](https://developers.google.com/apps-script/guides/clasp)
3. 先在 GAS 網頁新增空專案，在「專案設定」取得 Script ID。Script ID 不是 Google 文件 ID，也不是 Web App 部署 ID。
4. 在本機儲存庫根目錄建立 `.clasp.json`，用自己的 ID 取代範例：

```json
{
  "scriptId": "YOUR_APPS_SCRIPT_ID",
  "rootDir": "gas"
}
```

5. 檢查目的地是自己新建的專案，再上傳：

```sh
clasp push
```

若 CLI 詢問是否更新 manifest，核對是本專案的設定後確認。專案附帶的 `.claspignore` 只上傳 GAS 程式及 manifest，不會上傳測試、README、單檔備份或本機設定。

6. 回到 GAS 瀏覽器，執行 `initializeProject` 並完成授權。接著照 [安裝說明](部署指南.md) 設定兩個 API、建立索引、部署 Web App、填 `WEB_APP_URL` 並連接 LINE。

`clasp push` 只更新原始碼，不會自動更新已發布的版本化 Web App。每次修改後仍需在「管理部署」選新版本。不要依賴 `clasp run` 代替瀏覽器執行；一般 Web App 不一定配置成可由執行 API 呼叫的專案。

`.clasp.json`、`.clasprc.json`、`.env*` 與個人設定不應提交 Git。金鑰只存 GAS 指令碼屬性，不寫進原始碼。使用自己的新專案安裝，不要把他人的 Script ID 複製進本機設定。

## 修改後交付

編輯 `gas/`，不要只改生成的 `dist/Code.gs`。完成後重新測試並執行 `npm run bundle`，將分檔與單檔一起提交；GitHub Actions 會檢查一致性。

`npm run bundle` 同時產生 START_HERE.html，內含完整單檔與 manifest；不要只更新其中一份。發布時讓 package.json、appVersion_()、安裝頁與下載包使用同一版本號，學生才可比對實際部署版本。

修改內建模擬履歷時，同步更新 [範例文字](模擬履歷_陳沐言_AI自動化工程師.txt) 與 `starterResumeText_()`；文件檢查會防止兩者不同。程式更新不會覆蓋學生已建立的 Google 文件，需要學生自己修改既有內容。

不要提交真實履歷、索引檔、訪客問題、正式 API Key 或含 key 的 Webhook 網址。公開儲存庫只包含教學程式與虛構資料。

## v1.3.0 開發與驗證

### 學生閱讀程式的順序

GAS 分檔與單檔安裝版皆有繁體中文模組導覽、函式說明及關鍵步驟註解。建議先看 `Config.gs` 與 `Admin.gs` 理解設定，再從 `Webhook.gs` 的 `doPost`／`handleEvent_` 追到 `Chat.gs`、`Knowledge.gs`、`Gemini.gs`。圖片流程看 `Images.gs`，主題分類看 `QuickTopics.gs`，短期記憶看 `Conversation.gs`，作品副本及校對看 `Portfolio.gs`、`PortfolioStore.gs` 與 `Review.gs`。

註解會說明函式用途、資料存在哪、何時呼叫外部 API，以及為何必須先核對公開範圍或同步狀態。函式名稱以底線結尾是內部共用函式，不是要學生逐一手動執行；GAS 上方操作請依安裝步驟選擇管理入口。

`web/image-review.html` 是校對頁來源。`npm run bundle` 先以 `scripts/review-ui.mjs` 產生 `gas/ReviewUi.gs`，再輸出單檔與離線安裝頁。管理資料檔及索引皆私有；只將主人同意的獨立作品副本設成持連結者可讀。管理憑證只存雜湊與到期時間，不可把完整連結放入公開測試紀錄。

Quick Reply 保存在索引的 `quickTopics`，每個來源組只屬於一個主題；未變內容直接沿用。相容舊索引僅補建主題時，若模型失敗仍保留原索引；公開內容真的更動，則不以舊資料回答。

選用瀏覽器驗證：安裝 Playwright 與 Chromium 後執行 `node scripts/check-review-browser.mjs`。可用 `PLAYWRIGHT_MODULE` 指定模組位置、`CHROME_PATH` 指定瀏覽器，桌面／手機截圖寫入忽略的 `local/review-browser/`。此測試模擬 google.script.run，涵蓋響應版面、校對、文字注入、公開同意、撤回及憑證失效；仍須在自己的正式 GAS 與 LINE 實測。
