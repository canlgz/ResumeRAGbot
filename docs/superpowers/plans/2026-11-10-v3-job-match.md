# V3 零打字職缺對照＋日曆預約 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓人資在 LINE 用文字或截圖貼職缺 → 確認條件 → 取得逐字核對過的燈號熱圖與面談問題 → 帶著問題邀約，並可選真實日曆空檔預約。

**Architecture:** 新增 `gas/JobMatch.gs`（狀態機＋AI 呼叫＋驗證）、`gas/JobMatchView.gs`（純 Flex 組裝）、`gas/JobMatchImage.gs`（LINE 圖片下載＋職缺截圖辨識）、`gas/Booking.gs`（空檔計算＋日曆寫入）。`Webhook.gs` 在 `handleContact_` 之後呼叫 `handleJobMatch_`；邀約與通知沿用 v2 `Contact.gs`。草稿存 `CacheService`，以雜湊 key 隔離訪客。

**Tech Stack:** Google Apps Script V8、LINE Messaging API、Gemini API（`generateContent`、`batchEmbedContents`）、CalendarApp；Node 22+ `node --test` 搭配 `test/harness.mjs` 模擬。

**Spec:** `docs/superpowers/specs/2026-11-10-v3-job-match-design.md`

## Global Constraints

- 只改 `gas/` 分檔；`dist/Code.gs`、`START_HERE.html`、`gas/ReviewUi.gs` 只由 `npm run bundle` 產生（Task 8）。
- Windows 執行：本 repo 已設 `core.autocrlf=false`，新檔一律 LF 換行。
- 程式註解與使用者文字使用繁體中文，風格同 v2（`/** 【標題】說明 */`）。
- 職缺內容不寫 Doc、不進索引、不呼叫 `recordUnansweredQuestion_`、不寫 `console.log` 原文；只用 `safeLog_(code)`。
- 限制值（集中於 `JOB_MATCH_LIMITS_`）：文字總長 6000 字、截圖 3 張、條件 8 項、每項檢索 4 段、草稿 30 分鐘（1800000 ms）、`note` ≤ 40 字、`question` ≤ 60 字。
- 燈號：`supported` 有依據 `#2E7D32`、`partial` 部分相符 `#F9A825`、`unconfirmed` 待確認 `#BDBDBD`（灰色，不用紅色）。
- 摘要文字格式：`必要條件 X／Y 有依據・加分條件 X／Y 有依據`；不得出現「分數」「分」字樣。
- 一次 LINE 回覆最多 5 則訊息。
- 優先順序：邀約填寫中 > 職缺草稿 > 一般問答。
- 每個 Task 結束時 `node --test test/*.test.mjs` 必須全部通過（含 v2 原有 150 項）。
- Commit 只推到 `origin`（`guaisme/resume_v3`）的 `feature/v3-job-match-guaisme`，永不推 `upstream`。

## Review Focus

1. **LINE 重送同一事件到「開始對照」**：不得再次呼叫 Gemini；回覆上次結果。→ Task 3 測試 `retried run event reuses last messages`。
2. **邀約填寫中又貼職缺／點職缺對照**：文字要進邀約欄位，不被職缺流程吃掉。→ Task 1 測試 `invitation draft keeps priority over job match`。
3. **截圖辨識或貼上文字的全形／空白差異**：職缺原句核對須容忍標點空白，但不容忍改寫。→ Task 2 測試 `criteria quote tolerates spacing and fullwidth punctuation`。
4. **快取被提早清除後按舊卡片或繼續打字**：不呼叫 Gemini、不進一般 RAG、不寫待補充問題，回「已過期」。→ Task 1、Task 2 測試 `evicted draft never reaches RAG`、`stale card button is rejected`。
5. **兩位人資同時選同一時段**：第二位要拿到重新列出的空檔，不重複建立事件。→ Task 7 測試 `second pick of a taken slot relists`。

## Postback 與資料格式（所有 Task 共用）

| data | 意義 |
| --- | --- |
| `jm:start` | 開始（也接受文字「職缺對照」「比對職缺」） |
| `jm:done:<draftId>` | 完成輸入 |
| `jm:lv:<draftId>:<cid>:must` / `:plus` | 調整等級 |
| `jm:del:<draftId>:<cid>` | 刪除條件 |
| `jm:add:<draftId>` | 下一則文字成為新條件 |
| `jm:run:<draftId>` | 開始對照 |
| `jm:retry:<draftId>` | API 失敗後重試目前階段 |
| `jm:restart` | 重新輸入／換職缺 |
| `jm:cancel` | 取消（也接受文字「取消」，但邀約草稿存在時歸邀約） |
| `jm:invite:<draftId>` | 帶問題進邀約 |
| `book:list:<invitationId>` / `book:pick:<invitationId>:<startMs>` | 日曆預約 |

`draftId` = `sha256_(Utilities.getUuid()).slice(0, 16)`。條件 id：`C1`…`C8`。

草稿：

```js
{ id, stage: 'input' | 'confirm' | 'adding' | 'result',
  texts: [string], imageCount: number, title: string,
  criteria: [{ id, text, level: 'must' | 'plus' | 'unspecified', quote, source: 'jd' | 'hr' }],
  excluded: [string],
  results: [{ id, status: 'supported' | 'partial' | 'unconfirmed', evidence: [{ chunkId, section, quote }], note, question }],
  fingerprint, expiresAt, lastEvent, lastMessages, failedStage: null | 'extract' | 'match' }
```

Gemini 回應 schema 的根屬性名稱固定（測試靠它分辨呼叫）：拆條件 → `criteria`；對照 → `results`；截圖 → `jobText`。

測試共用 helper（放在 `test/job-match-fixture.mjs`，Task 1 建立）：

```js

export function jobFixture({ criteria, results, jobText } = {}) // createGas + syncKnowledgeBase；
//   generateContent 依 schema 根屬性回 candidate(criteria / results / jobText)；

```

### Task 3: 逐項檢索、對照與引用降級

**Files:**
- Modify: `gas/JobMatch.gs`, `test/job-match.test.mjs`

**Interfaces:**
- Consumes: v2 `loadIndex_(cfg)`、`readPublicSource_(cfg)`、`rankChunks_(query, vector, chunks, ranking)`、`normalizeVector_`、`embeddingRequest_`、`quoteSource_`
- Produces:
  - `embedCriteria_(criteria, cfg) -> number[][]`（**1 次** `batchEmbedContents`，task `RETRIEVAL_QUERY`，查詢字串 `條件：<text>\n職缺原句：<quote>`）
  - `matchCriteria_(draft, cfg, prepared) -> { status: 'ok', results, fingerprint } | { status: 'stale' | 'unavailable', message }`：索引不存在 → unavailable；`source.fingerprint !== index.fingerprint` → stale（「履歷資料正在等待同步…」）；每項 `rankChunks_(..., { minSimilarity: cfg.minSimilarity, topK: 4 })`；**1 次** `generateContent`（schema 根 `results[{id, status, evidence[{chunkId, quote}], note, question}]`）；生成後再讀一次 fingerprint
  - `validateMatch_(raw, criteria, hitsById: { [cid]: Hit[] }) -> results`：
    - 每項只用 `hitsById[cid]` 驗證 quote；全部 quote 失敗或零片段 → `status = 'unconfirmed'`、`evidence = []`
    - `unconfirmed`／`partial` 缺 `question` 時補 `請分享與「<text>」相關的具體經驗或成果。`
    - `note` 截 40 字、`question` 截 60 字（以 `Array.from` 計字）
    - 模型漏掉的條件補為 `unconfirmed`；多出的 id 丟棄

系統提示詞必須包含：只能引用提供的片段；不得由工具名稱推論年資、熟練度或主導角色；資料沒寫時標 `unconfirmed`，說明「履歷未提及」而非「不具備」。
