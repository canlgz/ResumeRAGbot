# v3 候選版本說明（Jie-Ting）

以 v2.0.0 為起點的個人候選版本，不是官方第三版。目標：把人資看履歷的 30 秒流程搬進 LINE——**名片篩選 → 貼職缺比對 → 留下邀約**。

- 作者：GitHub [Jie-Ting](https://github.com/Jie-Ting)
- 起點：v2.0.0（commit `54501c9`）
- 開發分支：`feature/v3-job-match`
- 程式版本：2.1.0（`checkDeployment` 可分辨新舊部署）
- 相關討論：<https://github.com/canlgz/ResumeRAGbot/discussions/1>

| 區塊 | v2 | 本版 |

### 比對怎麼判斷

- **地點只比縣市**：職缺「台北市內湖區」、履歷「台北或新北」→ 符合；任一方寫遠端也算。
- **年資比年數**：「3 年以上」vs 履歷「四年三個月」→ 符合；履歷沒寫年數 → 待確認。
- **學歷**比學位高低與科系關鍵字（「資訊相關科系」對「資訊管理學系」→ 符合）。
- 以上三類用規則，不經模型。
- **技能／工具／證照／語言／經驗／特質／其他**：先用向量＋關鍵詞檢索履歷片段，再請模型一次判定；每個「符合」「不符」都必須附能對回檢索片段的逐字引用（沿用 v2 的 `quoteSource_`），對不回就降為「待確認」並註明。
- **履歷沒寫 ≠ 不會**：找不到依據一律「待確認」，只有履歷明寫相反事實才是「不符」。不給總分，薪資一律「面談確認」。
- 職缺整理也由模型完成，但每個條件都必須是職缺原文的片段（`SQL`、`GAS` 這類短名稱直接比對），模型不能加料。

### 資料與隱私

- 職缺內容只放在訪客專屬快取約 30 分鐘；不寫 Doc、不進履歷索引、不記入待補充問題。
- 人資在留邀約前比對過職缺，送出邀約時才把職缺標題與比對摘要（不含職缺全文）交給主人；貼職缺卡上寫明「除非你留下邀約，不會交給本人」。
- 名片的學校、年資、常用工具、三個標籤由同步時的 `homeProfile` 摘錄，仍須是公開正文逐字片段；「個性」只採主人自述（履歷寫「個性：…」），不由模型歸納。

## 安裝／從 v2 升級

1. 貼入新的 `dist/Code.gs`（或更新 `gas/` 全部 **19 個 .gs**），`appsscript.json` 不變。
2. 部署 → 管理部署 → 原部署 → 新版本。
3. 執行一次 `syncKnowledgeBase`：名片新增欄位（學校、年資、標籤）要重新摘錄。
4. 導覽卡小圖示預設從本分支的 GitHub 讀取；要改成自己的網址，在指令碼屬性加 `ICON_BASE_URL`（結尾不必加斜線）。
5. 名片若要顯示「個性」標籤，在履歷公開區加一行「個性：○○○○」（8 字內）。

## 已知限制與下一步

- 比對需兩次模型呼叫，實測約 10～20 秒；超長或極多條件的職缺可能接近 LINE 回覆時限，目前以 3000 字、必要 8 項、加分 6 項為上限。
- 地區只認台灣縣市名稱；海外或「北部」這類寫法會列待確認。
- 沒有量測比對的準確率；結果以「有無履歷依據」呈現，不宣稱命中率。
- 一次貼多個職缺目前是「先選一個比」，之後可考慮多張結果卡並排（上限 3）。
- 原先討論過的「人力銀行」方向（求職者／人資兩種身分、多份履歷）未納入本版。
