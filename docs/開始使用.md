# 安裝勾選清單

第一次操作搭配 [詳細安裝說明](部署指南.md)，履歷內容不熟悉時看 [填寫指南](履歷填寫指南.md)。

## 帳號

- [ ] 使用年滿 18 歲的個人 Gmail，從頭到尾同一個 Google 帳號；不符合時先告知老師（[原因](部署指南.md#0-準備帳號)）。

## 程式與自動履歷

- [ ] 下載最新安裝包並全部解壓縮，用瀏覽器開啟和 README.md 同一層的 START_HERE.html。
- [ ] 建立自己的 GAS 專案並改名 ResumeRAGbot，貼入 [單檔程式](../dist/Code.gs) 並儲存。
- [ ] 顯示 appsscript.json，貼入 [manifest](../gas/appsscript.json)。
- [ ] 儲存後，從左側「檔案」欄點回「程式碼.gs／Code.gs」。
- [ ] 在上方執行／偵錯附近的函式下拉選單選 `initializeProject`，按執行。
- [ ] 授權：審查權限 → 選帳號 →（未驗證提示）進階 → 前往 ResumeRAGbot → 勾「選取全部」→ 繼續。
- [ ] 複製執行記錄中「履歷文件：」後的網址，打開含填寫指引及模擬履歷的文件。
- [ ] 指令碼屬性已自動產生 `RESUME_DOC_ID`、`DOC_TAB_IDS`、`WEBHOOK_TOKEN`、`DISPLAY_NAME`、`GEMINI_MODEL`、`BOT_ENABLED`。

## API 與索引

- [ ] 在 LINE Official Account Manager 建立官方帳號，「設定 → Messaging API」啟用並建立 Provider。
- [ ] LINE Developers → 頻道 → Messaging API 分頁最下方，Issue 並複製 Channel access token (long-lived)。
- [ ] AI Studio 建立自己的 API Key。
- [ ] 專案設定 → 指令碼屬性 → 按「編輯指令碼屬性」。
- [ ] 新增 `LINE_CHANNEL_ACCESS_TOKEN` 與 `GEMINI_API_KEY`。
- [ ] 修改既有的 `DISPLAY_NAME`，不要新增第二個同名屬性。
- [ ] 按「儲存指令碼屬性」。
- [ ] 執行 `testLineConnection`，status 為 ready、botName 為自己的帳號。
- [ ] 執行 `checkSetup`，credentials 三項為 true、document 為 ready。
- [ ] 執行 `syncKnowledgeBase`，再執行 `checkSetup` 確認 index 為 ready。
- [ ] 執行 `testResumeAnswer`，沒有紅色錯誤；再執行 `checkSetup`，`answerTest` 為 OK 或 GEMINI_OK。

## 部署與 LINE

- [ ] 部署 → 新增部署作業 → 點「選取類型」旁齒輪 → 網頁應用程式。
- [ ] 以「我」執行、「所有人」可存取，部署後複製結尾為 /exec 的網址。
- [ ] 用「編輯指令碼屬性 → 新增指令碼屬性」把 `/exec` 網址填入 `WEB_APP_URL` 並儲存。
- [ ] 無痕視窗開啟 /exec，版本號與安裝包及 checkSetup.version 相同。
- [ ] 執行 `checkDeployment`，`status=ready`，`editorVersion` 與 `webAppVersion` 都等於安裝包版本；不同時先更新原部署，不能靠重複同步解決。
- [ ] 執行 `showWebhookUrl`，複製含 key 的完整結果。
- [ ] LINE Developers → Messaging API 分頁 → Webhook URL 按 Edit 貼上 → Update → Verify 成功 → 開啟 Use webhook。
- [ ] Auto-reply／Greeting messages 旁按 Edit，在「回應設定」關閉自動回應訊息與加入好友的歡迎訊息，Webhook 保持開啟。
- [ ] 掃 Messaging API 分頁的 QR Code 加好友，收到首頁；傳「選單」也能收到。
- [ ] 問已記載的問題，答案符合文件並有來源。
- [ ] 問未知問題，確認「待補充問題」新增記錄。

## 自己的履歷與維護

- [ ] 按填寫指南替換虛構資料，保留公開標記。
- [ ] 同步後重問，驗證更新。
- [ ] 需要時才執行 `installHourlySync`，不需要時用 `removeHourlySync`。
- [ ] 完成 [課堂驗收](課堂實作.md)，作業不附金鑰或含 key 的網址。

## 使用圖片內容

- [ ] 將履歷／證照等圖片真正插入公開區，初次建議使用行內圖片。
- [ ] 執行 `syncKnowledgeBase`，再看 `checkSetup.publicImages` 與 index 狀態。
- [ ] 執行 `previewImageText` 核對辨識文字，再由 LINE 提問圖片中的資訊。
- [ ] 換圖或刪除圖片後重新同步，詳見 [圖片知識庫](圖片知識庫.md)。

## 作品卡片與代表主題（v1.6.2）

- [ ] `checkSetup.quickReplies` 顯示 ready、labels 有「我是誰」「快速一覽」及最多四個互不重複的適性特色。
- [ ] 在 LINE 提問、看首頁與作品圖庫時，Quick Reply 沿用同一份；公開內容改動後同步才重建。
- [ ] 執行 `openImageReview`，從記錄開啟含 `#` 憑證的完整管理連結，只供本人使用。
- [ ] 在校對頁對照原圖，修正辨識後儲存並同步，LINE 回答使用校正內容。
- [ ] 選擇願意公開的作品副本並逐張開放，按「檢查 LINE 作品卡片」。
- [ ] LINE 輸入「作品圖庫」，可看圖並選擇「問這件作品」，再追問「配色呢」。
- [ ] 測試「清除對話」與撤回預覽，詳見 [操作與驗收](作品卡片與圖片校對.md)。

## 日後更新程式

- [ ] 完整程式與 manifest 來自同一版本，原設定與履歷保留；單檔、分檔不混貼。
- [ ] 儲存後重新整理 GAS，確認 checkSetup.version 等於下載包版本。
- [ ] 管理部署 → 編輯原部署 → 版本選「新版本」→ 部署；GAS 的快照編號不是安裝包版本。
- [ ] checkDeployment 為 ready 後，再看 checkSetup.index；ready 可直接測試，needs_sync 才重建索引。
- [ ] v1.3.x 或更早版本首次升級本版，執行一次 syncKnowledgeBase 補建主題選單；內容未變時沿用原向量。

## 聯繫與邀約通知

- [ ] GAS → 專案設定 → 編輯指令碼屬性，新增／修改 OWNER_LINE_USER_ID，按儲存；不是填 @ID 或 Token。
- [ ] 本人已加入自己的 bot 為好友且未封鎖。
- [ ] 新邀約確認前不通知，確認後 Email 與本人 LINE 都收到內容；再次點同一確認卡不重複通知。

- [ ] 了解舊邀約不會自動補寄，寄送結果與實際收到通知都需確認。完整步驟見 [聯繫與邀約通知](聯繫與邀約通知.md)。
