# 學生安裝檢查紀錄

日期：2026-10-19。對照公開 v1.0.0 下載包走過新安裝流程，再修正為 v1.1.0。檢查涵蓋下載檔、瀏覽器安裝頁、設定誤填與程式流程。

## 真正執行的檢查

- 不使用 GitHub 登入資訊，從公開 Release 下載 v1.0.0 ZIP，HTTP 200，SHA-256 與公開資產相符。
- 在全新暫存資料夾解壓縮，執行原版 41 項測試及單檔／文件檢查；原測試全部通過，但下列設定問題仍可重現，因此補上針對這些問題的測試。
- 用真正的 Chrome 瀏覽器從 file:// 開啟新版 START_HERE.html，確認載入沒有 JavaScript 錯誤、不需載入遠端腳本。
- 實際點擊複製程式、manifest 及屬性名稱，讀取剪貼簿逐字比對；再模擬剪貼簿權限拒絕，確認完整文字已選取供手動複製。
- 檢查桌面與 390px 手機寬度，沒有橫向溢出；桌面與手機畫面已視覺檢查。
- 直接執行實際要交給學生的 dist/Code.gs，模擬新建文件、填設定、LINE Token 檢查、向量同步、Webhook、選單、RAG 回答、未知問題記錄與資料更新。這一項使用模擬服務，不是真實雲端授權。

## 重現與修正

| 問題 | 原行為／學生可能卡住之處 | v1.1.0 修正 |
| --- | --- | --- |
| ZIP 沒有明確入口 | .gs、JSON、Markdown 多種檔案，學生不確定先開哪個 | 根目錄提供 START_HERE.html，內含複製按鈕與分階段完成判斷 |
| 複製權限被拒絕 | 檔案頁的剪貼簿 API 不一定可用 | 自動嘗試一般複製，失敗時展開並選取全文，提示 Ctrl+C／⌘C |
| 沿用教學占位值 | YOUR_GEMINI_API_KEY 被 checkSetup 判成 credentials=true | 空白與占位值不算已設定，列出應填的屬性與下一步 |
| 複製含前後空白 | Token／ID 原樣送出，可能造成驗證或讀取失敗 | 讀取設定時去除前後空白，空白文件 ID 仍會自動建立範例 |
| 誤貼完整文件網址 | 被當成 ID 傳給 Google | 可從標準 Google 文件網址擷取 ID；分頁仍依設定選取 |
| WEB_APP_URL 貼到舊的含 key 網址 | 正式 /exec 仍因 query 被拒絕 | 擷取正式主網址，產生目前有效 key；/dev 與外部網址仍拒絕 |
| 索引 JSON 損壞 | checkSetup 把錯誤放在 document，誤導學生重建履歷 | document 保留 ready、index 顯示 INDEX_INVALID，提示重建索引 |
| Token 尚未確認就部署 | 直到 LINE 沒回應才發現 Token 或頻道不對 | 提供 testLineConnection，確認有效性與帳號名稱，不發送訊息 |
| 直接在編輯器按 doPost | 只看到入口密鑰錯誤，無法知道正確測試方式 | 顯示應改執行 initializeProject／checkSetup，LINE 入口仍供真實事件使用 |
| 找不到初始化建立的文件 | JSON 中網址不容易辨認 | 記錄額外列出「履歷文件」直達網址與可讀的「下一步」 |
| 更新後仍使用舊部署 | 儲存程式後誤以為 Web App 已更新 | 公開部署頁顯示版本，可與安裝包及 checkSetup.version 比對 |
| 設定未完成就換入口密鑰 | 更換後才發現部署網址無效 | 先檢查正式網址，失敗時保留原密鑰 |

## 模擬與真實帳號驗證的界線

此次沒有替學生登入新的 Google／LINE 帳號、通過其 Google 同意畫面、消耗其 Gemini 配額，或替其 LINE 頻道完成真正的收送訊息。自動文件建立、API 與問答流程的回歸測試採模擬服務，不能當成以上實機步驟已通過。

新版安裝頁與指南把實機檢查設為必要關卡：

1. 本人執行 initializeProject 並授權，從記錄打開自己的文件。
2. testLineConnection 為 ready，帳號名稱正確。
3. syncKnowledgeBase 成功、index=ready，testResumeAnswer 回答符合原文。
4. 無痕開啟正式 /exec，頁面版本與安裝包一致，沒有登入限制。
5. LINE Verify 後仍須傳「選單」及真正提問，核對已知答案與未知問題記錄。

帳號政策、API 額度、模型可用性及 Google／LINE 部署權限，必須由每位學生的帳號檢查；具體步驟及錯誤碼見 [詳細安裝說明](部署指南.md)。
