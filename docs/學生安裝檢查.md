# 學生安裝檢查紀錄

## v1.3.1：從作品切換主題的誤判（2026-10-26）

v1.3.0 的測試未涵蓋「已有作品記憶，再點另一個自動主題」。系統生成的「介紹這個主題」被辨識成追問，因此同時套用新主題與舊作品限制，交集為空，誤寫待補充問題。

修正後，主題按鈕及完整主題名稱開始新的查詢；真正的追問才沿用指向。新增會先失敗、修正後通過的回歸測試，並檢查每個主題確實有檢索證據、只使用自己的來源。來源對應異常和 AI 未能概述不再冒稱履歷缺資料。新增 `testQuickReplyTopics` 與管理頁「測試主題問答」，以實際索引及 Gemini 驗收，不只檢查 LINE 訊息格式。本機測試增為 101 項。


## v1.3.0：作品、校對、追問與代表主題（2026-10-26）

新增學生操作頁 [作品卡片與圖片校對](作品卡片與圖片校對.md)，離線安裝頁增加步驟 9。安裝包仍為單檔貼上，不需另外設定 HTML、資料庫、管理員帳號或 Cloudflare。

本機 95 項自動測試通過，新增測試包含限時管理憑證、本人擁有的私有管理檔、圖片校正與還原、來源移除後撤回副本、匿名圖片格式／尺寸檢查、作品追問與記憶隔離、3–6 主題的來源完整互斥分配、選單重用，以及舊索引補建選單失敗時保留相容索引。另以 Chromium 模擬 GAS 客戶端，在 1360px 與 390px 寬度驗證校對、公開同意、撤回、文字注入與憑證失效，無橫向溢出。

以上本機與模擬瀏覽器測試不代表已使用學生帳號完成 Google 授權或 LINE 收訊。學生仍須照新版完成判斷，親自在自己的 LINE 檢查作品圖片、連續追問與更新後選單。

## 真正執行的檢查

- 不使用 GitHub 登入資訊，從公開 Release 下載 v1.0.0 ZIP，HTTP 200，SHA-256 與公開資產相符。
- 在全新暫存資料夾解壓縮，執行原版 41 項測試及單檔／文件檢查；原測試全部通過，但下列設定問題仍可重現，因此補上針對這些問題的測試。
- 用真正的 Chrome 瀏覽器從 file:// 開啟新版 START_HERE.html，確認載入沒有 JavaScript 錯誤、不需載入遠端腳本。
- 實際點擊複製程式、manifest 及屬性名稱，讀取剪貼簿逐字比對；再模擬剪貼簿權限拒絕，確認完整文字已選取供手動複製。
- 檢查桌面與 390px 手機寬度，沒有橫向溢出；桌面與手機畫面已視覺檢查。
- 直接執行實際要交給學生的 dist/Code.gs，模擬新建文件、填設定、LINE Token 檢查、向量同步、Webhook、選單、RAG 回答、未知問題記錄與資料更新。這一項使用模擬服務，不是真實雲端授權。

## 模擬與真實帳號驗證的界線

此次沒有替學生登入新的 Google／LINE 帳號、通過其 Google 同意畫面、消耗其 Gemini 配額，或替其 LINE 頻道完成真正的收送訊息。自動文件建立、API 與問答流程的回歸測試採模擬服務，不能當成以上實機步驟已通過。

新版安裝頁與指南把實機檢查設為必要關卡：

1. 本人執行 initializeProject 並授權，從記錄打開自己的文件。
2. testLineConnection 為 ready，帳號名稱正確。
3. syncKnowledgeBase 成功、index=ready，testResumeAnswer 沒有紅色錯誤，answerTest 為 OK（回答符合原文）或 GEMINI_OK。
4. 無痕開啟正式 /exec，頁面版本與安裝包一致，沒有登入限制。
5. LINE Verify 後仍須傳「選單」及真正提問，核對已知答案與未知問題記錄。

帳號政策、API 額度、模型可用性及 Google／LINE 部署權限，必須由每位學生的帳號檢查；具體步驟及錯誤碼見 [詳細安裝說明](部署指南.md)。

## v1.1.3：testResumeAnswer 出現 ANSWER_INVALID_EVIDENCE

學生回報步驟 5 執行 testResumeAnswer 時出現 `Error: ANSWER_INVALID_EVIDENCE`，再執行 checkSetup 也只是再要求執行 testResumeAnswer。

對照學生記錄的行號（validateAnswer_ 第 539 行、generateAnswer_ 第 525 行）與當時的 dist/Code.gs，錯誤來自「引用文字不在片段原文中」這一檢查：Gemini 已成功回應，金鑰與配額正常，回答也標示為有依據，但至少一段 quote 與履歷原文不是逐字相同。舊版用 `indexOf` 要求完全一致；範例履歷大量出現中英文與數字間的空格（例如「使用 pandas 整理 CSV」「2024 年 7 月」）及全形冒號，模型去掉空格、改用半形標點、加引號、用省略號串接兩段，或引用章節標題時都會被判失敗。checkSetup 不知道測試結果，所以只會重複同一個建議。

| 問題 | v1.1.3 修正 |
| --- | --- |
| 引用比對過於嚴格 | 比對前做 NFKC 全半形正規化、忽略空白與引號；省略號串接的每段需至少 4 字且依原文順序出現；章節標題視為原文；引用標錯片段 id 時，改標到真正含有該文字的片段。改寫、捏造或順序錯亂的引用仍會被拒絕 |
| 提示詞 | 要求 quote 直接複製原文、保留空格與標點、不用省略號串接 |
| 錯誤只有代碼 | testResumeAnswer 失敗時先在記錄寫出中文說明，再顯示原錯誤 |
| checkSetup 重複要求測試 | testResumeAnswer 結果存入 `LAST_ANSWER_TEST`，checkSetup 顯示 `answerTest`；通過後不再要求，失敗時說明錯誤碼代表的意思 |

本次沒有可用的 Gemini 金鑰，無法用真實模型重跑學生的題目並統計修正前後的失敗率；上述原因由錯誤行號與程式比對推定，修正以模擬回應的回歸測試驗證。

## v1.1.4：1.1.3 仍出現 ANSWER_INVALID_EVIDENCE

學生用 1.1.3 再測，記錄先出現新增的中文說明，接著仍是 `ANSWER_INVALID_EVIDENCE`（validateAnswer_ 第 562 行，即「引用找不到來源」的檢查）。1.1.3 只容許空白、全半形、引號與省略號差異；模型若省略原文中的括號說明（例如「公司：禾序數位工作室（虛構公司）。」引用成「公司：禾序數位工作室。」）、改用其他標點、把兩行合成一句或稍微改字，仍會失敗，而回答中只要一段引用失敗整題就失敗。

| 問題 | v1.1.4 修正 |
| --- | --- |
| 引用比對仍過嚴 | 比對時忽略空白與常見標點；改成計算引用中有多少比例是「至少 4 個字的原文連續片段」，達 80% 才通過。省略括號、改標點、合併兩行或跨兩個片段的引用可通過；捏造內容、明顯改寫或過短的片段仍會被拒絕 |
| 偶發的引用改寫 | 引用檢查失敗時自動重新產生一次回答，第二次仍失敗才回報 |
| 無法得知實際失敗的引用 | testResumeAnswer 失敗時列出「未對上原文的引用」與相符比例，只出現在履歷主人自己的執行記錄；LINE 訪客路徑仍只記錄錯誤碼 |

以範例履歷全部 57 行模擬常見改寫：去空格、換半形標點、加引號、省略號串接、省略括號說明，1.1.4 全數通過（舊的逐字比對分別只通過 23、0、0、7、53 行）。另用另一份虛構履歷的 87 行當作「不屬於本履歷的引用」，只有 1 行因與原文高度相同（「流程自動化工程師」）被接受。仍未取得 Gemini 金鑰，尚未以真實模型統計修正前後的失敗率；學生若再遇到，請提供記錄中「未對上原文的引用」幾行。

## v1.1.5：testResumeAnswer 不再因 AI 引用檢查而中斷安裝

安裝步驟要求每位學生執行 testResumeAnswer，但 `ANSWER_*` 只會在 Gemini 已成功回應後出現：金鑰、模型、索引都正常，失敗的是 AI 這一次的回答內容。以紅色錯誤呈現會讓學生以為安裝失敗、卡在同一步反覆重試。另確認一個舊專案仍執行 1.1.0 以前的程式（逐字 `indexOf` 比對，validateAnswer_ 第 110 行），顯示的就是這種錯誤；紅色 `ANSWER_*` 錯誤可用來判斷 GAS 內仍是舊版。

| 問題 | v1.1.5 修正 |
| --- | --- |
| AI 偶發的引用問題被當成安裝失敗 | testResumeAnswer 遇到 `ANSWER_*` 不再拋出錯誤，記錄「安裝設定正常」並將 answerTest 記為 `GEMINI_OK`；checkSetup 視同通過，不再要求重跑 |
| 真正的設定錯誤 | `GEMINI_HTTP_*`、缺少金鑰、索引未就緒等仍顯示錯誤，checkSetup 依錯誤碼提示處理 |
| 舊版留下的 `ANSWER_*` 結果 | checkSetup 說明那是舊版結果，再執行一次 testResumeAnswer 即更新 |
