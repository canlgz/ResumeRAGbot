# 聯繫本人、留下邀約與通知設定（v2.0.0）

先完成 [安裝指南](部署指南.md) 的 LINE 連線。每位學生使用自己的 Doc、Email 與 LINE userId，不要複製老師的設定。**Email 寄信授權只需由本人完成一次，LINE userId 只需設定一次；之後的新邀約會自動通知。**

## 訪客怎麼聯絡你

在 LINE 輸入「首頁」，第一張卡的「聯繫本人」會開啟聯繫卡。輸入「聯繫本人」「想約面試」「想合作」也能開啟。

- **Email 旁的小複製圖示**：點圖示複製信箱，再貼到慣用郵件服務撰寫寄出。圖示無法操作時，可點信箱本身取得純文字，再長按或右鍵複製。這些動作本身都不會寄信。
- **在 LINE 留邀約**：依序填公司／稱呼、職缺或合作內容、回覆方式、方便聯繫時段（可略過）。看完確認內容後，按「確認送出」才保存並通知。

未確認的草稿約保留 30 分鐘，也可能提前失效；輸入「取消」或「首頁」可離開。填寫內容不送 Gemini、不寫入 Doc、不進入 RAG。通知成功不代表面試或合作已排定。

## 1. 在 Doc 填入真正能收信的 Email

1. 打開自己的履歷文件，在 `[[PUBLIC]]` 與 `[[/PUBLIC]]` 之間新增「公開聯絡方式」標題。
2. 下一行寫 `Email：你的實際收件信箱`，將文字換成自己可收信的地址。建議只放一個主要聯絡信箱，避免多個地址時選到非預期收件人。
3. **不要沿用範例的 `example.invalid` 或 `example.com` 信箱**，這些範例網域不會用來寄送。不要只把 Email 放在圖片裡，或放在公開標記之外。
4. 執行 `syncKnowledgeBase`，讓首頁、摘要和 RAG 都反映更新。聯繫卡與通知收件人另外直接讀 Doc 最新正文，不依賴舊索引，也不從圖片辨識或 AI 猜測信箱。

Email 欄位會展示給訪客，因此填入願意公開的聯絡信箱。通知寄給這個 Doc 信箱，**不會自動改寄 Google 登入帳號**。寄件則使用執行 GAS 的 Google 帳號，無須提供 Gmail 密碼、SMTP 或應用程式密碼。

## 2. 完成 Google 寄信授權與測試

1. 確認 Code.gs 與 appsscript.json 都來自 v2.0.0 安裝包。manifest 已包含 `https://www.googleapis.com/auth/script.send_mail`；只更新 Code.gs 而漏掉 manifest 會缺少寄信權限。
2. 從 GAS 左側「檔案」點回 **程式碼.gs／Code.gs**，在上方函式下拉選單選 **`enableInvitationEmailNotifications`**，按「執行」。不要執行 `doPost`。
3. 若 Google 要求授權：按「審查權限」→ 選擁有 GAS 的帳號 → 確認是自己的專案 → 同意寄送郵件及程式所需權限。若首次初始化已同意全部權限，這次可能不再詢問，屬正常情況。
4. 執行成功後，記錄會顯示「寄信權限已就緒，測試信已送交 Google…」。到 **Doc 裡填寫的信箱**找主旨「【ResumeRAGbot】邀約通知啟用測試」，也檢查垃圾郵件。
5. **舊專案升級者：授權完成後才發布原部署的新版本。** 只在編輯器執行成功，不會自動把 LINE 正式程式換成新版。依 [升級指南](版本更新.md) 完成部署與 `checkDeployment`。

每次手動執行這個函式都會寄一封啟用測試信；它不是排程，不需要每天執行，也不會自動重寄以前的邀約。Google 寄信額度以帳號為準，程式沒有另外加一個自訂寄信額度。[MailApp 權限與寄信說明](https://developers.google.com/apps-script/reference/mail/mail-app) · [GAS 配額](https://developers.google.com/apps-script/guides/services/quotas)

## 3. 設定自己的 LINE userId

1. 用機器人建立者的帳號登入 [LINE Developers](https://developers.line.biz/console/)，選 **這個機器人所屬 Provider → Messaging API 頻道**。
2. 切到 **Basic settings** 分頁，找到 **Your user ID**，複製完整值。格式為大寫 `U` 加上 32 個小寫十六進位字元，共 33 個字元。
3. 這不是聊天暱稱、可搜尋朋友的 LINE ID、官方帳號的 `@...`、Channel ID、Channel secret，也不是 Channel access token。不同 Provider 的 userId 可能不同，請從本機器人的頻道複製。[LINE 官方取得 userId 說明](https://developers.line.biz/en/docs/messaging-api/getting-user-ids/)
4. 回到 GAS 左側齒輪 **「專案設定 → 指令碼屬性 → 編輯指令碼屬性」**。
5. 新增屬性名稱 **`OWNER_LINE_USER_ID`**，值貼上剛才的 Your user ID；已存在同名項目就修改原值，不新增第二筆。不加引號、不留前後空白，最後按 **「儲存指令碼屬性」**。
6. 用上述 userId 對應的本人 LINE 帳號，掃描該頻道 Messaging API 分頁的 QR Code，**將自己的 bot 加為好友且不要封鎖**。

不需要綁定碼或額外伺服器，也不會將第一位傳訊息的訪客當成主人。userId 存在自己的指令碼屬性，不用寫進 Doc、原始碼或交作業的截圖。

已部署 v2.0.0 時，修改這項屬性會套用到下一份新邀約，**不需要重新部署或重新同步**。尚未填寫或格式無效時不推播 LINE，Email 通知仍可運作。清空／刪除這項屬性即可停用 LINE 通知。

## 4. 用一份完整邀約驗收

1. 確認 `checkDeployment` 的 `status=ready`，`editorVersion` 與 `webAppVersion` 都是 `2.0.0`。
2. 在 LINE 傳「首頁」→ 第一張「聯繫本人」→「在 LINE 留邀約」。可以請同學操作，也可以自己填一份內容明確寫「安裝測試」的邀約。
3. 依序填完四欄，先停在確認畫面：這時不應收到 Email 或主人 LINE 推播。
4. 按「確認送出」。訪客收到保存回覆；主人應收到一封新邀約 Email，以及一則「您收到一份新邀約」的 LINE Push。兩者都有邀約內容與回覆方式。
5. 再按同一張確認卡，應不新增邀約、不重複通知。想再測一次，請重新開始「留下邀約」並建立新的一份。
6. 若邀約的「回覆方式」填的是完整單一 Email，通知信會設定 Reply-To，可以在郵件程式按回覆；電話、LINE ID 或混合文字則依內容自行聯繫。機器人不會替你自動答覆邀約者。

LINE Push 使用官方帳號的訊息額度；Email 使用 Google 寄信額度。兩者各自運作，一邊失敗不會刪掉邀約或阻止另一邊嘗試。平台接受不等於一定送達或已讀，仍以實際收到通知為驗收標準。[LINE 訊息類型與計費](https://developers.line.biz/en/docs/messaging-api/sending-messages/)

## 5. 需要整理邀約時才開收件匣

平常直接讀 Email 或 LINE 通知即可。要標記已處理或刪除記錄時：

1. GAS 選 `openInvitations` → 執行。
2. 從記錄複製「主人管理介面」後的完整網址，包含 `#` 後內容，在瀏覽器開啟。
3. 「收到的邀約」列出確認過的內容、處理狀態，以及 Email／LINE 通知結果。可標記已處理、改回待處理或刪除。

若已開啟圖片校對管理頁，也可切到「收到的邀約」。管理連結有效 20 分鐘，僅供本人使用。過期再執行 `openInvitations`；不要把完整管理網址寄給邀約者或上傳作業。

確認的邀約保存於自己的私人 Drive 管理 JSON，不是履歷 Doc。刪除收件匣記錄不會刪除已送出的信件或 LINE 訊息。舊邀約不會因升級、填入 userId 或重新授權而自動補寄。

## 排錯

| 現象 | 檢查與處理 |
| --- | --- |
| 找不到 enableInvitationEmailNotifications | 點回 `.gs` 檔案、儲存並重新整理；確認完整貼入 v2.0.0，沒有混用舊分檔 |
| 要求先填可收信 Email | 將實際地址放進 Doc 公開正文，標示 `Email：`；移除範例網域，不能只有圖片 |
| 缺少 script.send_mail 權限 | 貼入同版 manifest，再由本人執行授權函式；組織限制需由管理員處理 |
| Google 今日寄信額度已用完 | 等帳號額度恢復；這是 Google 限制，不是 RAG 問答次數限制。舊邀約不會自動補寄，可先查看收件匣或 LINE 通知 |
| Email 成功但未收到 | 確認 Doc 收件地址、垃圾郵件及信箱規則；「送交 Google」不保證送達 |
| LINE 沒通知，Email 有收到 | 確認 OWNER_LINE_USER_ID 正確、來自同 Provider；本人已加好友且未封鎖；用一份新邀約測試 |
| LINE quota_or_rate_limit／429 | 檢查官方帳號訊息額度或速率限制；既有邀約保留於收件匣 |
| LINE rejected | 檢查本頻道 Token、收件 userId 與訊息設定；勿貼完整 Token 排錯 |
| 通知結果待確認／delivery_unknown | 服務未確認成功，可能已送出；先檢查實際信箱／LINE。系統不盲目重寄，避免重複通知 |
| 仍只有保存回覆、沒有新通知功能 | 核對正式 `/exec` 是否 v2.0.0；只儲存編輯器或使用 `/dev` 不等於更新正式部署 |
| 私有收件匣保存失敗 | 訪客不會被告知已保存，也不會寄通知；處理 Drive 權限後再按確認 |

不需新增計時觸發條件；邀約確認事件本身就會執行通知。`testContactFlow` 等需要管理憑證的內部測試入口，不是學生直接從 GAS 空參數執行的步驟；請用上面的實際邀約流程驗收。
