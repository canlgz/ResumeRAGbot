# v3 候選：中英雙語介面、每週提問洞察與主人 LINE 補答（2.1.0）

> 這是 yuchi0610 以 v2.0.0 為基礎提出的**個人 v3 候選版本**，不是官方正式 v3。

## 想解決的問題

- **外籍主管或英文面試官看不懂中文履歷。** v2 只有在訪客「明確要求」時才可能改用其他語言，首頁、按鈕、來源標籤與資料不足提示都是中文。
- **主人不知道訪客在關心什麼。** v2 只把「答不出來」的題目寫進待補充區；答得出來的題目，主人無從得知哪些經歷最常被問。
- **補資料要開電腦。** v2 看到待補充問題後，主人要打開 Google 文件、手動寫進公開區、再到 GAS 執行同步，步驟多又容易忘。

三個功能串成一個循環：**訪客用自己的語言提問 → 主人從週報知道缺什麼 → 在 LINE 直接補答 → 機器人馬上變聰明。**

## 功能一：中英雙語介面（先選語言、隨時切換）

| 情境 | 行為 |
| --- | --- |
| 加好友 | 先跳出「中文／English」選擇卡，選完顯示對應語言的首頁 |
| 任何訊息下方的 Quick Reply | 最後一顆固定是語言切換鍵（中文模式顯示 `English`，英文模式顯示 `中文`），按下立即切換並重開首頁 |
| 英文首頁 | 三張卡片標題、按鈕、說明為英文；`我是誰`→`About me`、`快速一覽`→`Quick overview`；適性主題與個人特質使用同步時產生的英文翻譯 |
| 手打英文問題（沒有中文字、至少三個英文字母） | 用英文回答，來源標為 `Sources: 章節名稱`，並記住英文偏好 |
| 手打中文問題 | 這一題用中文；偏好不變，按鈕仍沿用目前語言 |
| 點主題按鈕、輸入「選單」等固定指令 | 沿用目前語言，不會被按鈕上的中文字誤判 |
| 英文提問但履歷沒有資料 | 用英文說明查無資料，仍把原問題寫進待補充區給主人 |
| Gemini 忙線（429／5xx） | 英文模式顯示英文說明與狀態碼 |

**防捏造規則不變**：履歷原文仍是中文，Gemini 用英文寫回答，但 `evidence.quote` 必須逐字複製中文原文，程式照 v2 的方式核對。公司、學校等專有名詞要求保留中文並在括號補英文說明，不可自創正式英文名稱。

英文的主題名稱（`labelEn`）、職務定位（`roleEn`）與特質（`traitsEn`）在**同步時**由同一次 Gemini 分類請求一起產生，問答時不增加 API 次數。只接受 ASCII 短文字，不合格時退回中文。既有 v2 索引在內容不變時也會補建一次英文名稱。

語言偏好以「專案 ID + userId」的雜湊為鍵，暫存約 6 小時，不保存原始 userId 或訊息。

## 功能二：主人每週提問洞察

每次問答在 LINE 回覆成功後，只累加匿名次數：

- 回答狀態：成功回答／資料不足／錯誤
- 語言：中文／英文
- 被引用的履歷章節（取自來源標籤）
- 交流目的：沿用 v2 的 `dialogueIntent`（初次認識、評估能力、關注成果…）

**不保存**問題原文、回答、userId。統計存在指令碼屬性 `INSIGHT_週一日期`，只保留最近 8 週。選單、說明、語言切換與主人指令都不計入。

報告範例：

```text
📊 陳沐言｜AI 自動化工程師｜每週提問洞察
統計期間：2026-11-09 ～ 2026-11-15（台北時間）

提問數：3 題（成功回答 2、資料不足 1）
回答率：67%
語言：中文 2 題、英文 1 題

最常被引用的履歷章節：
1. 專案作品 2 次

訪客交流目的（AI 依提問判斷）：
評估能力／職務適配 2 次

建議下一步：
• 有 1 題資料不足：打開履歷文件末尾的「待補充問題」……
• 有英文提問：檢查英文回答的專有名詞是否正確……
```

| 看報告的方式 | 操作 |
| --- | --- |
| GAS 編輯器 | 執行 `previewWeeklyInsight`，執行記錄顯示本週與上週 |
| LINE（主人） | 已設定 `OWNER_LINE_USER_ID` 時，主人本人傳「本週洞察」；其他訪客傳同樣文字只會當成一般問題 |
| 每週自動寄送 | 執行一次 `installWeeklyInsight`，每週一約 9 點寄上週報告：有 `OWNER_LINE_USER_ID` 用 LINE 推播，否則寄 Email 給自己。`removeWeeklyInsight` 可停用 |

LINE 推播會使用 LINE 官方帳號的訊息額度，每週一則。

## 功能三：主人在 LINE 一鍵補答

```text
主人：待補充
機器人：待補充問題（1 題）
        1. 你有駕照嗎？（2 次）
        回覆「補充 題號：答案」即可……
主人：補充 1：我有普通小客車駕照。
機器人：請確認要寫進履歷公開區的內容：問：你有駕照嗎？ 答：我有普通小客車駕照。
        [確認寫入] [取消]
主人：（按「確認寫入」）
機器人：已寫入履歷公開區…… ✅ 知識庫已同步，訪客現在可以查到這個答案。
```

- 只列出待補充表格中維護狀態為「待確認」的問題，最多 10 題；題號以清單快照為準，30 分鐘內有效，之後新增的問題不會讓題號錯位。
- 確認後寫入 `[[PUBLIC]]` 區的「## 補充問答」段落（沒有就自動在公開區結尾建立；已有就接在段落最後），格式為「問：…／答：…」，再把表格列標成「已補充（LINE）」並自動執行同步。
- **寫入的是主人輸入的原文，不經 AI 改寫。** 答案限 1～500 字，不能含 `[[`、`]]`，避免破壞公開標記；寫入前後都核對標記。
- 只認 `OWNER_LINE_USER_ID`。訪客傳「待補充」「補充 1：…」只會當成一般問題，按到 `fill:` 按鈕會回覆「僅限履歷主人使用」，都不會建立草稿或改文件。
- 同步失敗時文件仍保留，機器人提示到 GAS 執行 `syncKnowledgeBase`。

## 已知限制

- 語言只分中文與英文；日文、韓文因含漢字或無法判斷，會以中文回答。
- 邀約表單、作品圖庫與 v2 的部分系統提示仍為中文。
- 英文主題名稱與特質是 AI 翻譯，只做格式檢查，無法像中文原文一樣逐字核對；有誤時請同步重建，或在履歷補上正式英文名稱。
- 「交流目的」是 AI 依提問判斷，只供參考，不代表訪客真實身分或意圖。
- 統計是盡力而為：同時大量訊息取不到鎖時會略過該筆，不影響回答。
- 主人補答會觸發完整同步，回覆可能需要 10～20 秒；同步遇到 Gemini 忙線時需手動再同步。
