# v3 候選：中英雙語問答與主人每週洞察（2.1.0）

> 這是 yuchi0610 以 v2.0.0 為基礎提出的**個人 v3 候選版本**，不是官方正式 v3。

## 想解決的問題

- **外籍主管或英文面試官看不懂中文履歷。** v2 只有在訪客「明確要求」時才可能改用其他語言，而且來源標籤、資料不足提示仍是中文。
- **主人不知道訪客在關心什麼。** v2 只把「答不出來」的題目寫進待補充區；答得出來的題目，主人無從得知哪些經歷最常被問、訪客是來評估能力還是想合作。

## 功能一：中英雙語問答

| 情境 | 行為 |
| --- | --- |
| 手打英文問題（沒有中文字、至少三個英文字母） | 用英文回答，來源標為 `Sources: 章節名稱` |
| 手打中文問題 | 維持 v2 的繁體中文回答 |
| 輸入 `English`／`英文模式` | 切換英文模式，不呼叫 AI |
| 英文模式下點 Quick Reply 主題按鈕 | 沿用英文回答 |
| 英文模式下手打中文 | 這一題用中文，偏好不變；輸入 `中文` 才切回 |
| 英文提問但履歷沒有資料 | 用英文說明查無資料，仍把原問題寫進待補充區給主人 |

**防捏造規則不變**：履歷原文仍是中文，Gemini 用英文寫回答，但 `evidence.quote` 必須逐字複製中文原文，程式照 v2 的方式核對。公司、學校等專有名詞要求保留中文並在括號補英文說明，不可自創正式英文名稱。

語言偏好以「專案 ID + userId」的雜湊為鍵，暫存約 6 小時，不保存原始 userId 或訊息。

## 功能二：主人每週提問洞察

每次問答在 LINE 回覆成功後，只累加匿名次數：

- 回答狀態：成功回答／資料不足／錯誤
- 語言：中文／英文
- 被引用的履歷章節（取自來源標籤）
- 交流目的：沿用 v2 的 `dialogueIntent`（初次認識、評估能力、關注成果…）

**不保存**問題原文、回答、userId。統計存在指令碼屬性 `INSIGHT_週一日期`，只保留最近 8 週。選單、說明、語言切換等操作不計入。

報告範例：

```text
📊 陳沐言｜AI 自動化工程師｜每週提問洞察
統計期間：2026-11-09 ～ 2026-11-15（台北時間）

提問數：3 題（成功回答 2、資料不足 1）
回答率：67%
語言：中文 2 題、英文 1 題

最常被引用的履歷章節：
1. 專案作品 2 次

訪客交流目的（AI 依提問判斷）：
評估能力／職務適配 2 次

建議下一步：
• 有 1 題資料不足：打開履歷文件末尾的「待補充問題」……
• 有英文提問：檢查英文回答的專有名詞是否正確……
```

### 怎麼看報告

| 方式 | 操作 |
| --- | --- |
| GAS 編輯器 | 執行 `previewWeeklyInsight`，執行記錄顯示本週與上週 |
| LINE（主人） | 已設定 `OWNER_LINE_USER_ID` 時，主人本人傳「本週洞察」；其他訪客傳同樣文字只會當成一般問題 |
| 每週自動寄送 | 執行一次 `installWeeklyInsight`，每週一約 9 點寄上週報告：有 `OWNER_LINE_USER_ID` 用 LINE 推播，否則寄 Email 給自己。`removeWeeklyInsight` 可停用 |

LINE 推播會使用 LINE 官方帳號的訊息額度，每週一則。

## 已知限制

- 語言只分中文與英文；日文、韓文因含漢字或無法判斷，會以中文回答。
- 首頁卡片、Quick Reply 按鈕文字、邀約流程與 API 錯誤訊息仍為中文。
- 「交流目的」是 AI 依提問判斷，只供參考，不代表訪客真實身分或意圖。
- 統計是盡力而為：同時大量訊息取不到鎖時會略過該筆，不影響回答。
- 英文回答品質取決於 Gemini；中文履歷中的數字與專有名詞仍需主人自行抽查。
