# 在 Google 文件放入圖片，讓 RAG 搜尋圖片內容

從 v1.2.0 起，ResumeRAGbot 會在同步知識庫時，使用 Gemini 辨識 Google 文件圖片中的可見文字及清楚標示的數據，再建立文字向量。可用於履歷截圖、證照、課程成果與作品介面截圖。

沿用原本的 Google 文件、Gemini API Key 與 LINE 設定，不需要另外申請 Cloud Vision 服務或新增伺服器。

## 既有機器人更新

1. 從 [最新版本](https://github.com/canlgz/ResumeRAGbot/releases/latest) 下載，將新的 `dist/Code.gs` 完整換入原 GAS 專案；若使用分檔安裝，請加入新的 `Images.gs` 並更新其他分檔，不要同時貼入單檔版。
2. 儲存後，在「部署 → 管理部署」為原部署發布「新版本」。原指令碼屬性與履歷保留，通常可沿用原 Webhook URL。
3. 將圖片插入文件的公開區，再執行 `syncKnowledgeBase`。這次更新會要求重新建立一次索引；舊索引無法直接提供新增的圖片內容。
4. 執行 `checkSetup`，確認 `document` 與 `index` 為 `ready`，`publicImages` 為預期的圖片數。
5. 執行 `previewImageText` 核對轉寫結果，再到 LINE 詢問圖片中的內容。

首次安裝仍照 [安裝說明](部署指南.md) 操作，圖片功能已包含在單檔與 START_HERE.html 裡。

## 圖片放在哪裡

在 Google 文件用「插入 → 圖片」加入圖片，或貼入截圖。必須是文件中真正嵌入的圖片，不能只放圖片網址、PDF 附件或連到其他文件。

圖片和一般履歷內容使用相同公開範圍：

```text
[[PUBLIC]]
## 證照與學習
（在此處插入證照圖片，再刪除這行提示。）

## 專案作品
這是我負責的課程專題，以下為完成的介面截圖。
（在此處插入作品圖片，再刪除這行提示。）
[[/PUBLIC]]
```

兩個標記必須是 Google 文件中的實際文字，且各自獨立成行。只把標記畫在圖片裡，不會建立公開範圍。整張公開圖片都會送去辨識，請先移除圖片內不想公開的內容。

`[[PRIVATE]]` 內、公開區外、未選取分頁及「待補充問題」區的圖片，不會送出辨識。頁首、頁尾與註腳仍不處理。圖片刪除或移出公開區後，機器人會先停用舊答案，等待重新同步。

## 圖片排版

初次使用建議選行內圖片（In line），放在公開區內自己的段落。表格儲存格、清單段落的圖片也支援。

浮動／文繞圖圖片依「錨定段落」判斷公開範圍，視覺上移到其他位置不代表錨點也移動。若圖片錨定在 PUBLIC／PRIVATE 等標記段落，程式會顯示 `IMAGE_ANCHOR_AMBIGUOUS`，請改成行內圖片，或把錨點放到確定公開的普通段落。

Google 繪圖物件目前需要先匯出為 PNG／JPEG，再當圖片插入；不要將繪圖物件與一般圖片混為一談。

## 辨識後怎麼確認

`checkSetup` 只檢查來源與狀態，不會執行 OCR；圖片辨識只在 `syncKnowledgeBase` 中進行。

同步成功後選 `previewImageText` 執行，記錄會列出每張圖片的章節、分頁、狀態與轉寫文字，例如：

```json
{
  "section": "證照與學習｜圖片 1（OCR）",
  "tabId": "t.0",
  "status": "readable",
  "text": "證照名稱：虛構資料分析師。取得日期：2026 年 3 月。"
}
```

這裡是格式示例，不是真實證照。請核對自己的姓名、日期、成績、單位與數值。預覽只讀取已存好的結果，不再呼叫 Gemini，但轉寫文字會顯示在本人 GAS 的執行記錄中。

LINE 回答會標示「資料來源：證照與學習｜圖片 1（OCR）」等來源。可以測試「這張證照的名稱是什麼？」「哪一年取得？」「作品截圖上有哪些功能名稱？」。

OCR 不等於確認證照真偽，也不能只憑介面截圖推定本人貢獻。圖片不清楚或辨識錯誤時，換成清楚圖片再同步；重要資訊也可在圖片旁補上經本人確認的文字。

## 照片、沒有文字的圖片與圖說

這版擷取清楚可見的文字、表格欄位與明確標示的數字，不從人像推測年齡、身份或資歷，也不猜圖表未標示的數值。

沒有文字的照片會記為 `no_text`，不會編造履歷事實。若希望搜尋作品照片，請在公開區補上圖說，例如「這張照片是我製作的社團報名頁面，我負責介面與欄位驗證」。圖說本身可以被 RAG 搜尋。

## 模型、格式與費用

預設使用既有的 `GEMINI_MODEL` 辨識圖片；需要分開指定時，可新增選填屬性 `GEMINI_IMAGE_MODEL`，填入自己的專案可使用、支援圖片及結構化輸出的 Gemini 模型。`checkSetup.imageModel` 會顯示實際設定。

支援 PNG、JPEG、WebP、HEIC、HEIF，單張原始資料上限 10 MiB，保留編碼與請求內容的空間，以符合 inline 請求限制。通常使用清楚的 PNG／JPEG 截圖最容易檢查。[Gemini 圖片介面](https://ai.google.dev/gemini-api/docs/image-understanding)

圖片內容未變、模型相同且仍有有效索引快取時，不重做 OCR。只改旁邊的文字會重建需要的向量，並沿用相同圖片的辨識結果。換圖、改圖片模型，或索引快取被刪除／同步失敗清除後，可能需要重新辨識。

每次 LINE 問答仍使用原本的問題向量與生成 API，不會為同一張圖重新呼叫 OCR。圖片同步使用自己的 Gemini 配額與費用，可能比純文字同步花更多時間；較多圖片時請分批加入、同步並核對結果。

## 常見錯誤

| 錯誤碼／現象 | 處理方式 |
| --- | --- |
| `publicImages=0` | 圖片需真正嵌入文件，放在所選分頁的公開標記之間；確認不是 PDF、外部連結或繪圖物件 |
| `IMAGE_TYPE_UNSUPPORTED` | 改為支援的格式，例如 PNG／JPEG |
| `IMAGE_TOO_LARGE` | 將原圖縮小至 10 MiB 以下；縮小後仍需可清楚閱讀文字 |
| `IMAGE_EMPTY`／`IMAGE_READ_FAILED` | 重新插入圖片，確認文件可讀與圖片未損壞 |
| `IMAGE_ANCHOR_AMBIGUOUS` | 浮動圖片錨定在範圍標記上，改成行內圖片或移動錨點到普通公開段落 |
| `IMAGE_DRAWING_UNSUPPORTED` | 將 Google 繪圖先匯出為圖片，再插入文件 |
| `IMAGE_TEXT_UNREADABLE` | 圖片有文字但無法可靠閱讀，請用較清楚、較大的原圖 |
| `IMAGE_TEXT_INCOMPLETE`／`IMAGE_TEXT_INVALID` | 這次辨識未完成或格式異常，重試；內容太密時拆成多張清楚圖片 |
| `NO_SEARCHABLE_CONTENT` | 只有圖片但沒有可用文字，例如純照片；補上圖說或可閱讀的履歷文字 |
| `IMAGE_PREVIEW_NEEDS_SYNC` | 文件或圖片剛改過，先執行 syncKnowledgeBase |
| `SOURCE_TOO_LARGE` | 辨識後仍沿用原本約 60,000 字／100 片段限制，精簡知識庫或拆分內容 |
| `GEMINI_HTTP_429`／`403` 等 | 仍是 Google 專案的配額／頻率或權限問題，依安裝指南排查 |

辨識或重建失敗時不會發布一份缺掉圖片內容的部分索引，也不繼續使用已改動的舊資料。查看 GAS 同步記錄，修正問題後重新同步即可。
