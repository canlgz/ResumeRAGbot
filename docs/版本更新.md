# 更新既有機器人至 v1.6.2

初次安裝請看 [部署指南](部署指南.md)。本頁給已經有 Doc、索引與 LINE Webhook 的同學。

## 升級順序：貼入 → 授權 → 更新原部署 → 核對 → 同步

1. 從 [v1.6.2 Release](https://github.com/canlgz/ResumeRAGbot/releases/tag/v1.6.2) 下載安裝 ZIP，全部解壓縮，再開 START_HERE.html。
2. 保留原 GAS 專案、指令碼屬性、履歷文件、Drive 索引／管理檔與原部署。不要刪除 RESUME_DOC_ID、DOC_TAB_IDS、WEB_APP_URL 或金鑰，也不必新建履歷。
3. 單檔安裝：用新版「複製完整程式」取代原 Code.gs 全文，再用同包 manifest 取代 appsscript.json。分檔安裝：更新 `gas/` 全部 **18 個 `.gs`** 及 manifest，新增 Contact.gs、OwnerLine.gs；移除已取消功能的舊 Evidence.gs（若有）。不要把單檔與分檔混貼。
4. 儲存完成後，關閉同專案其他舊編輯分頁，再重新整理。若忘了關掉舊分頁而儲存，可能把新版程式覆寫回舊版。
5. 在 Doc 公開聯絡方式填入實際可收信的 Email，回到 `.gs` 執行 `enableInvitationEmailNotifications`，完成新增寄信權限授權並收到測試信。詳見 [Email 與 LINE 設定](聯繫與邀約通知.md)。這一步不必先同步，避免舊正式版本與新編輯器不同時觸發版本保護。
6. 「部署 → 管理部署」選目前 LINE 使用的原部署 → 鉛筆「編輯」→ 版本選 **「新版本」** → 部署。不要另建第二個正式網址，除非你確定也要更換 LINE 的 Webhook。
7. 執行 `checkDeployment`：`status=ready`，`editorVersion` 和 `webAppVersion` 都應為 **1.6.2**。GAS 顯示「版本 2／版本 40」等是部署快照編號，不是套件版本，學生的編號不必與老師相同。
8. 初次從 v1.3.x 或更早版本升級，執行一次 `syncKnowledgeBase`，補建新的固定入口、適性主題、首頁資料與肖像預覽。相同圖片及可沿用向量會使用快取，不會覆蓋原履歷。若你已經使用 v1.6.2 且 `checkSetup.index=ready`、內容沒改，不必因再次下載而重跑同步。
9. 在指令碼屬性設定自己的 `OWNER_LINE_USER_ID`，加入自己的 bot 為好友；LINE 傳「首頁」，檢查三張卡、主題與聯繫入口，再用一份新邀約確認 Email 和 LINE 都有通知。

若 checkDeployment 回報不同，先改正原部署版本，不要一直重跑同步。若是 unreachable／unrecognized，檢查正式 `/exec`、公開權限與網路；它不等於已確認版本不同。需要協助時只交版本、狀態及錯誤碼，不交金鑰或管理連結。

## v1.6.2 統一收錄的功能

| 功能 | 目前行為 |
| --- | --- |
| 三張小型首頁卡 | 第一張肖像／姓名／聯繫本人；第二張特質；第三張與 Quick Reply 同源的主題 |
| 隨時回首頁 | 「首頁」「選單」「回首頁」「履歷首頁」均可叫出，不限加入好友時 |
| 肖像 | 沿用公開介紹中的肖像，同步準備獨立公開預覽；沒有肖像則使用原生幾何人物，不補圖進 Doc |
| Quick Reply | 固定「我是誰」「快速一覽」＋最多四個適性特色；特色來源互斥分組，不足時不湊數 |
| 作品與校對 | 圖片內容可檢索；作品可逐張開放圖文卡片；AI 辨識結果可校對並同步，另存私人管理資料 |
| 短期記憶 | 約 10 分鐘內追問同一作品；切換主題不再被舊作品範圍干擾 |
| 聯繫與邀約 | 從 Doc 讀 Email，邀約四欄確認後保存；通知到 Doc Email 與指定主人 LINE |
| 管理與註解 | 私人邀約收件匣、Email／LINE 通知狀態、繁體中文程式註解 |

沒有「展開答案依據」功能；回覆仍可顯示資料來源文字。歷史訊息的舊按鈕只告知已停用，不會重新啟用。
