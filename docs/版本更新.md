# 升級至第三版 v3.2.0

第三版在第二版的全部功能上，新增給人資使用的「人資模式」與技能 × 需求證據熱圖。直接安裝這一版即可，不必逐版升級。

初次安裝請看 [部署指南](部署指南.md)。本頁給已經有 Doc、索引與 LINE Webhook 的同學。先找到自己目前的版本：執行 `checkDeployment`，看 `editorVersion`。

## 從 v3.0.0／v3.1.0 升級到 v3.2.0

v3.2.0 新增 HrInsights.gs，並修改 HrReview.gs、Contact.gs、Line.gs、Config.gs；沒有新增權限、指令碼屬性或索引格式。

1. 依下方第 1–5 步貼入新版程式並更新原部署。單檔安裝直接取代 Code.gs；分檔安裝要**新增 HrInsights.gs**，共 20 個 `.gs`。
2. 執行 `checkDeployment`，兩邊都應為 **3.2.0**；不必重跑同步或重新授權。
3. 在 LINE 輸入「經歷時間軸」，確認每段期間都能在 Doc 找到原文；輸入「成果拆解」選一個專案，確認四格都是原文或「履歷未提及」；完成一次人資對照後按「轉給主管」，確認摘要在 300 字內。
4. 從 v3.0.0 升級時，另外在 LINE 進入人資模式：第 2 題按「貼職缺說明」貼一段 JD，確認拆出的需求都在原文中；在確認卡試「移除」與「逐項對照」；完成後按「帶入邀約」，確認第 2 題帶入了職位與待確認條件。

## 從第二版 v2.0.0 升級：貼入 → 更新原部署 → 核對

第三版沒有新增權限、指令碼屬性或索引格式，第二版的索引可以直接沿用。

1. 從 [v3.2.0 Release](https://github.com/canlgz/ResumeRAGbot/releases/tag/v3.2.0) 下載安裝 ZIP，全部解壓縮，再開 START_HERE.html。
2. 保留原 GAS 專案、指令碼屬性、履歷文件、Drive 索引／管理檔與原部署，不要刪除任何屬性或金鑰。
3. 單檔安裝：用新版「複製完整程式」取代原 Code.gs 全文，再用同包 manifest 取代 appsscript.json。分檔安裝：更新 `gas/` 全部 **20 個 `.gs`** 及 manifest，並**新增 HrReview.gs 與 HrInsights.gs**。不要把單檔與分檔混貼。
4. 儲存完成後，關閉同專案其他舊編輯分頁，再重新整理，避免舊分頁把新版程式覆寫回去。
5. 「部署 → 管理部署」選目前 LINE 使用的原部署 → 鉛筆「編輯」→ 版本選 **「新版本」** → 部署。不要另建第二個正式網址。
6. 執行 `checkDeployment`：`status=ready`，`editorVersion` 和 `webAppVersion` 都應為 **3.2.0**。
7. **不必**重跑 `syncKnowledgeBase`，也不必重新授權。`checkSetup` 的 `index` 仍應為 `ready`。
8. 在 LINE 點「人資模式」，回答三題並按「開始對照」，確認收到熱圖、待確認條件與面談問題，且熱圖有色格子的原文都能在 Doc 找到。

## 從第一版升級：貼入 → 授權 → 更新原部署 → 核對 → 同步

第一版沒有第二版新增的寄信權限與首頁資料，要多做授權和一次同步。

1. 同上第 1–4 步下載並貼入 v3.2.0。分檔安裝時，另外新增 Contact.gs、OwnerLine.gs，並移除已取消功能的舊 Evidence.gs（若有）。
2. 在 Doc 公開聯絡方式填入實際可收信的 Email，回到 `.gs` 執行 `enableInvitationEmailNotifications`，完成新增寄信權限授權並收到測試信。詳見 [Email 與 LINE 設定](聯繫與邀約通知.md)。這一步不必先同步，避免舊正式版本與新編輯器不同時觸發版本保護。
3. 依上方第 5–6 步更新原部署，`checkDeployment` 兩邊都應為 **3.2.0**。GAS 顯示「版本 2／版本 40」等是部署快照編號，不是套件版本，學生的編號不必與老師相同。
4. 執行一次 `syncKnowledgeBase`，補建固定入口、適性主題、首頁資料與肖像預覽。相同圖片及可沿用向量會使用快取，不會覆蓋原履歷。
5. 在指令碼屬性設定自己的 `OWNER_LINE_USER_ID`，加入自己的 bot 為好友；LINE 傳「首頁」，檢查三張卡、主題與聯繫入口，再用一份新邀約確認 Email 和 LINE 都有通知，最後試一次人資模式。

若 checkDeployment 回報不同，先改正原部署版本，不要一直重跑同步。若是 unreachable／unrecognized，檢查正式 `/exec`、公開權限與網路；它不等於已確認版本不同。需要協助時只交版本、狀態及錯誤碼，不交金鑰或管理連結。

## 第三版新增的功能

| 功能 | 目前行為 |
| --- | --- |
| 人資模式入口 | Quick Reply 最後一項、首頁第三張卡按鈕，或輸入「人資」「人資模式」 |
| 三個問題 | 應徵職位、必要技能或條件、加分條件或工作情境（可略過）；確認卡可開始對照、重新填寫或取消；草稿約 30 分鐘有效 |
| 技能 × 需求熱圖 | 最多 5 項需求 × 5 個技能，四級為明確證據、相關經驗、間接、未提及；每個有色格子都通過履歷原文核對 |
| 待確認與面談問題 | 沒有依據的需求列為待確認，另附最多 3 題面談問題與資料來源；熱圖不是錄取分數 |
| 資料保護 | 人資輸入交給 Gemini 分析，只暫存在快取，分析後清除；不寫入 Doc、收件匣、索引或執行記錄 |
| 與邀約的關係 | 同一時間只保留一份草稿：開始人資模式會結束未完成的邀約，按「聯繫本人」或「留下邀約」也會結束人資草稿 |
| 貼職缺說明（v3.1） | 第 2 題可貼整份 JD（2000 字內），AI 拆出條件；每項都要在原文中找到，年齡、性別、婚育、宗教、健康、國籍等條件一律略過；JD 原文不保存 |
| 確認卡刪改（v3.1） | 「移除：需求」刪除單項（第 6 項起會遞補），「修改需求」回到第 2 題並顯示目前內容 |
| 逐項對照（v3.1） | 每項需求各自檢索、合併最多 12 段，一次批次嵌入加一次生成；摘要標示「逐項檢索」 |
| 帶入邀約（v3.1） | 對照完成後，職位與待確認條件可帶進 LINE 邀約第 2 題，直接採用或補充；確認送出後才保存與通知 |
| 經歷時間軸（v3.2） | 輸入「經歷時間軸」或在第 1 題點選；期間都要通過原文核對，空窗超過 6 個月、工作重疊、任職未滿 12 個月由程式計算並轉成中性面談問題 |
| 成果拆解（v3.2） | 輸入「成果拆解」選專案，四格（情境、任務、行動、結果）只顯示原文；找不到標「履歷未提及」並給追問，成果沒數字時標「成果未量化」 |
| 轉給主管（v3.2） | 對照完成後按「轉給主管」，取得 300 字內可複製轉傳的摘要；不呼叫 AI，摘要只暫存到草稿到期 |

## 第二版收錄並保留的功能

| 功能 | 目前行為 |
| --- | --- |
| 三張小型首頁卡 | 第一張肖像／姓名／聯繫本人；第二張特質；第三張與 Quick Reply 同源的主題，另有「人資模式」按鈕 |
| 隨時回首頁 | 「首頁」「選單」「回首頁」「履歷首頁」均可叫出，不限加入好友時 |
| 肖像 | 沿用公開介紹中的肖像，同步準備獨立公開預覽；沒有肖像則使用原生幾何人物，不補圖進 Doc |
| Quick Reply | 固定「我是誰」「快速一覽」＋最多四個「類型：主題」特色，最後固定一個「人資模式」；特色來源互斥分組，不足時不湊數 |
| 作品與校對 | 圖片內容可檢索；作品可逐張開放圖文卡片；AI 辨識結果可校對並同步，另存私人管理資料 |
| 短期記憶 | 約 10 分鐘內追問同一作品；切換主題不再被舊作品範圍干擾 |
| 聯繫與邀約 | 從 Doc 讀 Email，邀約四欄確認後保存；通知到 Doc Email 與指定主人 LINE |
| 管理與註解 | 私人邀約收件匣、Email／LINE 通知狀態、繁體中文程式註解 |

沒有「展開答案依據」功能；回覆仍可顯示資料來源文字。歷史訊息的舊按鈕只告知已停用，不會重新啟用。
