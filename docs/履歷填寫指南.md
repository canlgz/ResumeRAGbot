# 把模擬履歷改成自己的內容

初始化後已經有完整範例，不需要從空白文件開始。先用範例完成機器人測試，再把虛構的人物、公司、學校與成果替換成自己的真實資料。

## 只要記住兩個必要標記

```text
[[PUBLIC]]
你願意讓機器人回答的履歷內容，寫在這裡。
[[/PUBLIC]]
```

這兩行各佔一整行並保持成對即可。**不要求固定段落順序、標題名稱或欄位。** 自然段落、條列都可以。Google 文件的「標題 1／標題 2」或文字 `## 專案作品` 有助於分段，但不是每筆資料都要用固定表格。

字體、字級、顏色不會改變文字內容；只有圖片中的字不會被讀入。想讓機器人提供作品網址，請把完整 https 網址寫成可見文字。

## 方法一：直接修改已建立的範例

| 範例位置 | 換成什麼 |
| --- | --- |
| 陳沐言、AI 自動化工程師 | 自己的姓名或公開稱呼、目前科系／方向 |
| 四年三個月工作經驗 | 自己實際經歷；在校生可寫年級與學習方向 |
| Python、SQL 等技能 | 自己實際用過的技能與使用情境 |
| 虛構公司與職務 | 實習、工讀、社團、志工；沒有就刪除這些段落 |
| 三個模擬專案 | 自己的課程專題、個人作品或團隊專案 |
| 範例節省時間與百分比 | 有測量才寫自己的數據，沒有就描述實際完成的功能 |
| 示範學校與 Email | 真實且願意公開的資料；不想公開的項目可刪除 |

不要保留示範公司的名字或成果數字，讓人誤以為是自己的經驗。也不要把「會閱讀教學」寫成「已熟練實作」；機器人只會根據你寫的內容回答。

## 先回答這六個問題，就有履歷素材

1. 我是誰，目前在學什麼，想找什麼工作或合作？
2. 我用過哪些工具，各用來完成什麼事？
3. 我做過哪個作品，它要解決什麼問題？
4. 團隊裡哪些部分是我親自負責的？
5. 最後完成了哪些功能，有什麼可展示或可驗證的結果？
6. 我願意公開哪些聯絡方式或作品連結？

沒有工作經驗可以寫課程專題、實習、工讀、社團或志工。沒有獎項或證照就不必設該段，也不需要填滿所有範例欄位。

## 學生專題範例

以下同樣是虛構示例，請用自己的事實替換，不是要照抄經歷：

```text
[[PUBLIC]]
## 個人介紹
我是林同學，目前就讀資訊管理學系，正在學習網頁開發與資料處理。
希望尋找能參與網站或自動化工具開發的實習機會。

## 專業技能
用 HTML、CSS 與 JavaScript 製作過課程專題的使用者介面。
使用 Google Apps Script 將表單資料整理到 Google Sheets。

## 課程專題：社團器材借用系統
問題：社團原本透過聊天訊息登記器材借用，容易漏掉歸還狀態。
團隊：三人課程專題。
本人負責：借用表單、歸還狀態頁面與輸入欄位檢查；資料庫由另一位同學負責。
做法：以網頁表單登記借用，將狀態寫入 Google Sheets。
成果：完成新增借用、查詢與歸還三個流程，並在課堂展示操作。
限制：目前是課程原型，尚未實際部署給全校使用，沒有正式使用者成效數據。

## 聯絡方式
實習聯繫請由本人提供公開聯絡管道；目前文件未提供 Email。
[[/PUBLIC]]
```

這樣就能詢問「做過什麼專題？」「本人負責什麼？」「有正式上線嗎？」。成果不必硬寫百分比，有具體功能與限制就能說明工作內容。

## 方法二：讓 AI 協助整理自己的素材

若不熟悉履歷寫法，可以把下面提示詞連同自己的素材交給可使用的 AI 助理，再人工核對。這是可選的寫作輔助；機器人不會自動替你編造履歷。

```text
請將我提供的真實素材整理成繁體中文履歷，供 Google 文件 RAG 機器人使用。

要求：
1. 只能使用我提供的事實，不得編造公司、日期、技能熟練度、證照或成果數字。
2. 不清楚的地方先列問題問我；沒有資料的欄位可以省略。
3. 沒有工作經驗時，使用課程專題、社團、志工或實習經驗。
4. 區分個人貢獻與團隊成果，專案說明包含問題、本人角色、做法、成果與限制。
5. 最後的履歷以 [[PUBLIC]] 開始、[[/PUBLIC]] 結束，兩個標記各佔一行。
6. 標題可用 ##，正文用自然段落或條列；待確認問題放在公開標記外。
7. 只列我明確同意公開的聯絡方式。

我的素材：
公開稱呼與目前背景：
求職或合作方向：
使用過的技能與情境：
作品／專題的名稱與目標：
我親自負責的部分：
完成的功能、真實成果與限制：
其他經驗：
願意公開的聯絡方式或網址：
```

檢查生成內容後，把履歷放進自己的文件；不要在既有 PUBLIC 區塊內再貼另一組 PUBLIC 標記。若 AI 回傳了整份含標記的履歷，先選取舊的整個公開區塊再替換，避免重複巢狀。

## 寫完後做這三步

1. GAS 執行 `syncKnowledgeBase`。
2. 執行 `checkSetup`，確認 document 與 index 都為 `ready`。
3. 在 LINE 問三題：自我介紹、專案本人貢獻、履歷沒有提供的資訊，對照文件核對。

資料剛改但未同步時，機器人會提示等待同步。只改文件不必重新部署程式。

## 「待補充問題」怎麼處理

這個區域會自動記錄沒有足夠答案的問題，但檢索沒找到不代表文件一定沒有。先查看記錄原因及原文，確認是否真的需要補充。

要讓答案被機器人使用，請寫進 PUBLIC 區塊再同步。只在待補充表格填答案或把狀態改成「已補充」，不會更新知識庫。已處理列可刪除或保留註記；不要刪掉維護區外圍的成對標記。
