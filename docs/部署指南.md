# ResumeRAGbot 詳細安裝說明

學生使用自己的 Google、LINE 與 Gemini 帳號安裝。本指南以**瀏覽器複製安裝**為主，不需要 Node.js、Git、clasp、Cloudflare 或外部伺服器。想用本機工具再看 [開發指南](開發指南.md)。

Email 授權、LINE userId 與通知步驟核對日期：2026-10-26；其餘帳號準備說明沿用既有指南。平台畫面、模型可用性與額度可能調整，文中附官方連結供核對。

## 0. 準備帳號

| 項目 | 用途 |
| --- | --- |
| Google 帳號 | 擁有 GAS、履歷與索引，整個過程使用同一帳號；建議年滿 18 歲的個人 Gmail |
| LINE 帳號／Business ID | 建立自己的官方帳號與 Messaging API 頻道 |
| Google AI Studio 使用資格 | 建立 Gemini API Key，專案須能使用生成與向量模型 |
| 電腦瀏覽器與 LINE | 設定程式、加入好友並測試 |

**年齡與學校帳號：** [Gemini API 條款](https://ai.google.dev/gemini-api/terms) 要求使用者年滿 18 歲。Google Workspace for Education 帳號未滿 18 歲時，即使學校開啟 AI Studio 也無法使用，畫面會顯示「You do not have access to Google AI Studio」。[AI Studio 與 Workspace 帳號](https://ai.google.dev/gemini-api/docs/workspace)

學校 Workspace 帳號也可能限制外部服務、文件權限或匿名 Web App。如果沒有「所有人」存取選項，請管理員確認政策，或使用允許部署的帳號；把 Google 文件公開不能解決 Web App 權限問題。不符合上述資格的學生，請先與老師確認替代方式，不要借用他人的帳號或金鑰。

每位學生建立自己的設定。GitHub 提供程式，不會替你提供共用金鑰、API 額度或執行環境。

## 1. 建立 GAS，貼入程式與 manifest

**建議方式：** 到 [最新 Release](https://github.com/canlgz/ResumeRAGbot/releases/latest) 的 Assets 下載 `ResumeRAGbot-v版本號.zip`，先全部解壓縮，再用瀏覽器開啟解壓縮後資料夾裡、和 README.md 放在一起的 **START_HERE.html**。它已內含程式及 manifest，能直接按鈕複製，不需要知道 `.gs` 應用哪個軟體開啟。

Windows 請先「全部解壓縮」，不要只在壓縮檔預覽裡開啟；若 HTML 被文字編輯器打開，改用「開啟方式 → 瀏覽器」。GitHub 網頁上的 HTML 原始碼預覽不會執行安裝頁，必須下載後開啟。若改用 Code → Download ZIP，解壓縮後可能多一層 `ResumeRAGbot-main` 資料夾，點進去找和 README.md 同一層的 START_HERE.html。

按鈕若因瀏覽器權限無法自動複製，會展開並選取完整文字，請按 Ctrl+C（Mac：⌘C）。不要只複製可見的前幾行。這個頁面不要求輸入金鑰，金鑰只填到 GAS。

下面是相同流程的手動複製版本：

1. 開啟 [dist/Code.gs](../dist/Code.gs)，點 **Raw** 查看純文字，複製全部內容。也可以從 GitHub 的 **Code → Download ZIP** 下載後，用文字編輯器開啟。
2. 開啟 [Google Apps Script](https://script.google.com/)，按左上「新專案」。點編輯器上方標題「未命名的專案」，改成 `ResumeRAGbot`，按「重新命名」。
3. 左側檔案欄點選 `Code.gs`（中文介面也可能顯示「程式碼.gs」），在程式區按 Ctrl+A（Mac：⌘A）全選並刪除預設 `myFunction`，貼上完整程式，按上方磁碟圖示「儲存專案」或 Ctrl+S（⌘S）。
4. 左側齒輪「專案設定」勾選「在編輯器中顯示『appsscript.json』資訊清單檔案」。
5. 回到編輯器，開啟 `appsscript.json`，完整換成 [gas/appsscript.json](../gas/appsscript.json) 的 JSON。不要貼入 Markdown 的三個反引號。
6. 儲存，等待編輯器完成儲存。此時畫面可能仍在 `appsscript.json`，請先從左側「檔案」欄點回 **程式碼.gs／Code.gs**，再進行初始化。

單檔已包含全部 18 個 `.gs` 分檔（含校對頁），**不要再同時貼入 gas/ 的分檔**。若選擇分檔安裝，則建立 18 個同名指令碼，逐一貼入內容，並移除單檔版；manifest 一樣要設定，不須另建 HTML 檔案。

這版使用 GAS 內建服務，不需在「服務」選單加 Google Docs／Drive 進階服務。瀏覽器安裝也不需要開啟 Apps Script API；clasp 路線才需要。[Google manifest 說明](https://developers.google.com/apps-script/concepts/manifests)

**完成判斷：** Code.gs 與 appsscript.json 已儲存，沒有語法錯誤。

## 2. 初始化，自動建立自己的履歷文件

1. 先從左側「檔案」欄點回 **程式碼.gs／Code.gs**，確認中央顯示的是程式碼，而非 `appsscript.json` 的 JSON。
2. 找到編輯器上方、「執行／偵錯」附近的 **函式下拉選單**，選 `initializeProject`。不要選 `doPost`，它是 LINE 呼叫的入口。
3. 按「執行」。跳出「需要授權」時按「審查權限」，選擇擁有此專案的 Google 帳號。
4. 若出現「Google 尚未驗證這個應用程式」：自己新建的專案都會顯示這個提示。確認是自己建立的專案後，點左下「進階」，再點「前往 ResumeRAGbot（不安全）」。若組織政策直接阻擋，先請管理員處理。
5. 權限清單請勾選 **「選取全部」**（或把每一項都勾起來），再按「繼續」。Google 允許只授權部分權限，但本程式每項都會用到；漏勾時，之後建立文件、同步、連 LINE 或安裝排程會出現權限錯誤。[Google 個別權限同意說明](https://workspaceupdates.googleblog.com/2025/01/granular-oauth-consent-in-google-apps-script.html)
6. 編輯器下方會打開「執行記錄」。前面是一長串 JSON，先看最後幾行：複製「履歷文件：」後的網址，貼到瀏覽器新分頁開啟；JSON 的 `documentUrl` 也指向同一份文件。
7. 你會看到自己的 Drive 中新建的 **「ResumeRAGbot｜模擬履歷（請修改）」**，包含頁首填寫指引、虛構人物陳沐言、技能、經歷與三個專案。

如果找不到 `initializeProject`，先確認已點回 `.gs` 檔案、完整貼入程式並儲存；等待編輯器完成載入，再打開函式下拉選單。

漏勾權限時，再執行一次 `initializeProject`，Google 會再次詢問缺少的權限。若沒有再詢問，到 [Google 帳戶的第三方連線](https://myaccount.google.com/connections) 移除 ResumeRAGbot 的存取權，再重新執行並勾選全部。

初始化會自動設定 `RESUME_DOC_ID`、實際分頁的 `DOC_TAB_IDS`，並產生隨機 `WEBHOOK_TOKEN`；也會建立預設的 `DISPLAY_NAME`、`GEMINI_MODEL`、`BOT_ENABLED`。左側齒輪「專案設定」最下方的「指令碼屬性」應看到這六項，不要刪除。重複執行會沿用已設定的文件，不會覆蓋學生修改。此步驟不呼叫 Gemini，還沒填 Key 也能建立文件。[Google 建立文件介面](https://developers.google.com/apps-script/reference/document/document-app#create(String))

此時 `document` 應是 `ready`。尚未填金鑰時，credentials 的兩個 API 欄位為 `false`、index 為 `missing` 是正常狀態，不是初始化失敗。

`checkSetup` 會依目前狀態列出「下一步」，不用自行解讀所有 JSON 欄位。如果文件正常但索引損壞，會保留 document=ready，將問題標在 index；不需要因此重建或清空履歷。

Google 授權用途：文件權限用於建立／讀取履歷及寫入待補充問題；Drive 用於私有索引、校對管理資料，以及主人逐張開放的獨立作品副本；外部請求用於 LINE／Gemini；排程權限用於選用的每小時同步；帳號 Email 身分權限用於確認管理函式由本人操作；另外的 `script.send_mail` 寄信權限用於邀約通知，不讀取 Gmail 收件匣。Google 顯示的服務權限範圍較廣，程式實際處理的是設定的履歷及自己建立的索引。

### 想沿用既有文件

在初始化前先到「專案設定 → 指令碼屬性」設定 `RESUME_DOC_ID`，就不會新建。初始化後也能改用其他文件，再同步索引。

```text
https://docs.google.com/document/d/YOUR_DOCUMENT_ID/edit?tab=t.abc123
```

`RESUME_DOC_ID` 建議填 `/d/` 與 `/edit` 中間的 ID；貼入完整 Google 文件網址時，程式也會擷取其中的 ID。`DOC_TAB_IDS` 仍需填實際 `t.abc123`；多個 ID 用逗號分隔，或用 `*` 讀所有分頁及子分頁。自己的執行帳號須有編輯權限，才能保存待補充問題。

原文件若刪除，先恢復或指定另一份；確定想重新產生範例時，刪除 `RESUME_DOC_ID` 屬性，再執行 `initializeProject`。不要在日常測試時反覆刪除 ID。

## 3. 建立 LINE 官方帳號並取得 Token

1. 開啟 [LINE Official Account Manager](https://manager.line.biz/)，用自己的 LINE 帳號登入；初次使用依畫面註冊 LINE Business ID。
2. 按「建立帳號」，依表單填寫帳號名稱（例如「王同學履歷」）、業種等必填欄位後送出。一般帳號即可，不需申請認證。
3. 進入該帳號管理頁，按右上「設定」，左側選「Messaging API」，按「啟用 Messaging API」。
4. 這個 LINE 帳號第一次使用 LINE Developers 時，會要求登錄開發者資訊：輸入姓名與 Email、同意條款。接著選擇 Provider：沒有的話建立新的 Provider，名稱可用自己的名字。Provider 指定後無法更換。若出現隱私權政策／服務條款網址欄位，可留空後確定。
5. 開啟 [LINE Developers Console](https://developers.line.biz/console/)，用同一個 LINE 帳號登入，點剛才的 Provider，再點和官方帳號同名、類型為 **Messaging API** 的頻道。
6. 點上方 **Messaging API** 分頁，捲到最下方 **Channel access token (long-lived)**，點 **Issue** 發行，再按旁邊的複製圖示。此教學使用固定 Token；其他 Token 類型另有到期／更新機制，本程式不會自動更新。
7. 回到 GAS，依 [第 5 節](#5-核對指令碼屬性) 的操作新增 `LINE_CHANNEL_ACCESS_TOKEN`，貼入完整 Token 並按「儲存指令碼屬性」。

儲存後先在函式下拉選單選擇並執行 **testLineConnection**。結果應為 `status: "ready"`，`botName` 是自己準備測試的官方帳號。這只讀取 LINE 帳號資訊，不發送訊息；若名稱不同，代表貼到另一個頻道的 Token，請先修正。若為 error，依 code／message 處理，再繼續部署。[LINE 帳號資訊介面](https://developers.line.biz/en/reference/messaging-api/#get-bot-info)

Messaging API 頻道需從官方帳號啟用後產生；不要照舊教學直接在 Developers Console 新建，也不要建立成 LINE Login 頻道。Channel secret 不是 Access Token，本專案不使用 LIFF。[LINE 官方流程](https://developers.line.biz/en/docs/messaging-api/getting-started/) · [Token 類型](https://developers.line.biz/en/docs/basics/channel-access-token/)

## 4. 建立 Gemini API Key

1. 開啟 [Google AI Studio API Keys](https://aistudio.google.com/apikey)，用同一個 Google 帳號登入；第一次需同意服務條款。看到「You do not have access to Google AI Studio」時，回到 [第 0 節](#0-準備帳號) 確認帳號資格。
2. 按「建立 API 金鑰／Create API key」，選擇 Google Cloud 專案；新帳號選 AI Studio 自動建立的預設專案或依引導建立，既有專案未出現時先匯入專案。
3. 複製金鑰，依 [第 5 節](#5-核對指令碼屬性) 的操作新增指令碼屬性 `GEMINI_API_KEY` 並儲存，不要寫進 Code.gs 或履歷文件。
4. 確認自己的專案能使用以下模型，並有可用的 API 配額。Gemini 聊天訂閱不等同 API 額度。

| 用途 | 設定 |
| --- | --- |
| 生成答案 | `GEMINI_MODEL` 預設 `gemini-3.5-flash-lite` |
| 文件與問題向量 | 程式使用 `gemini-embedding-001`，指定 768 維並正規化 |

若金鑰建立或使用遭拒，核對專案權限、API 限制及服務資格。現行 AI Studio 新建金鑰採授權金鑰；不要為排錯任意取消所有限制或使用別人的 Key。[API Key 說明](https://ai.google.dev/gemini-api/docs/api-key)

模型可用性見 [生成模型](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite) 與 [向量文件](https://ai.google.dev/gemini-api/docs/embeddings)。改 `GEMINI_MODEL` 時須選擇支援 `generateContent` 與結構化輸出的模型；不要只替換向量模型名稱，不同模型的向量空間與請求格式可能不同，需驗證並重建索引。

## 5. 核對指令碼屬性

GAS 左側齒輪「專案設定」，捲到最下方「指令碼屬性」。名稱區分大小寫，值不加額外引號或前後空白。

初始化後屬性已經存在，因此操作順序是：

1. 按 **「編輯指令碼屬性」**，畫面才會變成可修改。
2. 既有屬性（例如 `DISPLAY_NAME`）直接修改右欄的值；**不要再新增第二個同名屬性**。
3. 新的屬性按「新增指令碼屬性」，左欄填名稱、右欄貼值。
4. 按 **「儲存指令碼屬性」**。沒按儲存，程式讀不到新值。

[Google 指令碼屬性操作說明](https://developers.google.com/apps-script/guides/properties)

| 名稱 | 內容 | 是否自行設定 |
| --- | --- | --- |
| `RESUME_DOC_ID` | 自己的履歷文件 ID | 自動建立；使用既有文件才手動填 |
| `DOC_TAB_IDS` | 實際分頁 ID，或逗號分隔、多分頁 `*` | 自動設定；缺少時預設 `t.0` |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE 的完整 Access Token | 必填 |
| `GEMINI_API_KEY` | AI Studio 的 Key | 必填 |
| `OWNER_LINE_USER_ID` | 本頻道 Basic settings → Your user ID，U 開頭共 33 字元 | 接收邀約 LINE 通知時設定；不是 Token 或 bot ID |
| `DISPLAY_NAME` | 例如「王同學｜履歷測試」 | 初始化建立預設值「個人履歷」，**修改既有值** |
| `TAGLINE` | 首頁的一句介紹 | 選填 |
| `WEBHOOK_TOKEN` | 隨機 64 位十六進位秘密值 | 初始化產生，保留即可 |
| `WEB_APP_URL` | 正式 `/exec` 網址，不含 `?key=` | 第 7 步部署後必填 |
| `GEMINI_MODEL` | 預設 `gemini-3.5-flash-lite` | 初始化設定 |
| `GEMINI_IMAGE_MODEL` | 選填；圖片辨識模型，未填時沿用 GEMINI_MODEL，需支援圖片輸入 | 通常不必設定 |
| `MIN_SIMILARITY` | 預設 `0.4`，範圍 0～1 | 選填，初次請用預設 |
| `BOT_ENABLED` | `true` 啟用、`false` 暫停 | 初始化設定 |

`INDEX_*`、`LAST_SYNC_*`、`LAST_ANSWER_TEST`、`SYNC_LEASE`、`evt_*` 是程式管理的狀態，不用自行填入。沒有每日／每小時自訂問答額度。

## 6. 同步知識庫並在 GAS 測試

1. 執行 `checkSetup`。三項 credentials 應為 `true`，document 為 `ready`，publicChunks 大於 0。
2. 執行 `syncKnowledgeBase`。會使用 Gemini 向量 API，並在 Drive 建立私有「LINE 履歷 RAG 索引.json」。首次成功記錄 `SYNC_OK`。
3. 再執行 `checkSetup`，確認 index 為 `ready`。範例成功結果節錄如下；實際還會有部署狀態與 nextSteps：

```json
{
  "version": "1.6.2",
  "credentials": {
    "LINE_CHANNEL_ACCESS_TOKEN": true,
    "GEMINI_API_KEY": true,
    "WEBHOOK_TOKEN": true
  },
  "document": "ready",
  "publicChunks": 11,
  "index": "ready",
  "model": "gemini-3.5-flash-lite",
  "lastSync": "OK",
  "documentUrl": "https://docs.google.com/document/d/YOUR_DOCUMENT_ID/edit"
}
```

4. 執行 `testResumeAnswer`，確認 Gemini 能根據文件回答。這會使用 Gemini 配額，不傳 LINE 訊息；資料不足時也可能在文件記錄待補充問題。結果記錄在 checkSetup 的 `answerTest`，`OK` 或 `GEMINI_OK` 都代表這一步通過，checkSetup 不會再要求執行：
   - `OK`：記錄顯示回答及「資料來源」，可對照履歷核對內容。
   - `GEMINI_OK`：記錄顯示「安裝設定正常」。Gemini 已成功回應，只是這次 AI 的回答沒通過來源檢查，所以沒有顯示回答；這是 AI 偶發狀況，不是設定錯誤，直接繼續下一步。記錄同時列出「未對上原文的引用」，供老師了解原因。
   - 執行記錄出現紅色錯誤（例如 `GEMINI_HTTP_403`、`MISSING_GEMINI_API_KEY`）才是設定問題，依記錄的說明與[常見錯誤](#11-常見錯誤)處理後再執行。

credentials 為 true 只表示有填入非空、非範例占位值，不保證金鑰有效。前後空白會自動去除，但不能填 `YOUR_GEMINI_API_KEY` 等教學文字。Gemini 是否可用要看同步與回答；LINE Token 用 testLineConnection 檢查，收送訊息則要在第 8 步實測。若同步失敗，先修正再往下進行。公開內容不變時，再同步會沿用索引。

## 7. 部署網頁應用程式

1. 按編輯器右上藍色「部署」→「新增部署作業」。
2. 對話框左上「選取類型」旁有 **齒輪圖示**，點齒輪後選「網頁應用程式」。
3. 說明可填 `v1`。「執行身分」選 **我（自己的 Gmail）**；「誰可以存取」選 **所有人**，包含未登入者；不是「任何擁有 Google 帳戶的使用者」。
4. 點「部署」；若再次要求授權，照第 2 節完成並勾選全部權限。
5. 複製「網頁應用程式」下方、結尾是 `/exec` 的網址，按「完成」。不要複製上方的「部署作業 ID」。
6. 依 [第 5 節](#5-核對指令碼屬性)：「編輯指令碼屬性」→「新增指令碼屬性」，名稱 `WEB_APP_URL`、值貼上該網址（不加 `?key=`），按「儲存指令碼屬性」。
7. 回到編輯器執行 `showWebhookUrl`，複製執行記錄中的完整網址，格式如下：

```text
https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec?key=YOUR_GENERATED_WEBHOOK_TOKEN
```

這只是格式範例，不能直接用；必須使用自己執行函式得到的結果。如果在 WEB_APP_URL 誤貼了帶舊 key 的正式網址，程式會只取 /exec 主網址，再由 showWebhookUrl 加上目前有效的 key。`/dev` 仍會被拒絕：它只允許編輯者測試，與正式部署的 ID 可能不同，不能只換成 `/exec`。[Google Web App 說明](https://developers.google.com/apps-script/guides/web)

用無痕視窗開啟不含 key 的 `/exec`，應顯示「LINE 履歷助理已部署。版本 1.6.2」，版本應與自己的安裝包及 checkSetup.version 一致。若沒有版本號或仍是舊版，回到管理部署發布新版本。這只證明網頁能開啟，不代表 LINE 或 AI 已完成設定。含 key 的完整網址是入口密鑰，只貼到 LINE 後台。

接著執行 `checkDeployment`，確認 `status=ready`、`editorVersion` 與 `webAppVersion` 都是安裝包版本。`checkSetup.deploymentCheck` 也會列出同一項檢查。GAS 的「版本 1、版本 2…」只是專案快照編號，快照編號較大不代表內含的程式較新。

`version_mismatch` 表示已確認不同，應先更新原部署，不要重跑同步；同步會在清除索引前停止並回報 `DEPLOYMENT_VERSION_MISMATCH`。`unreachable`／`unrecognized` 表示無法確認，請檢查公開權限、網址與網路，不代表已證實版本不同。第一回尚未填 `WEB_APP_URL` 時，`not_configured` 是正常狀態，可先完成第 5 步的首次索引建立。

新版索引會記錄建立時的程式版本，顯示於 `checkSetup.indexBuiltWith`；舊索引未記錄時為 `unknown`，這不是錯誤。是否需要重建以來源指紋與 `index` 狀態判斷，不要求每次修補程式都重新呼叫 Gemini。

## 8. 連接 LINE 並實測

1. [LINE Developers Console](https://developers.line.biz/console/) → 自己的 Provider → 自己的 Messaging API 頻道 → 上方 **Messaging API** 分頁 → **Webhook settings**。
2. 在 Webhook URL 旁按 **Edit**，貼上剛才產生的完整秘密網址，按 **Update**。
3. 點 **Verify**，看到 Success 後開啟下方 **Use webhook** 開關。
4. 同一分頁的 **Auto-reply messages** 或 **Greeting messages** 旁按 **Edit**，會開啟 LINE Official Account Manager 的「設定 → 回應設定」。關閉「自動回應訊息」及「加入好友的歡迎訊息」，並確認「Webhook」為開啟。本程式會處理 follow 事件，加入好友時自動送出履歷首頁。
5. 用手機 LINE 掃描 **Messaging API** 分頁上方的 QR Code 加好友；若已是好友，直接傳「選單」。
6. 看到履歷首頁後，傳「每週營運報表自動化省了多少時間？」並對照文件。

設定與加好友流程見 [LINE 建立機器人說明](https://developers.line.biz/en/docs/messaging-api/building-bot/)。可啟用 webhook redelivery，但 GAS 已回傳成功的應用錯誤仍不保證重送。

**Verify 成功不等於所有設定正確。** 無效 key 的請求也會被程式忽略並回傳網頁回應，因此必須再傳「選單」驗證入口與 Token，再提問驗證 RAG。不要在 GAS 編輯器手動執行 `doPost` 代替測試，它需要 LINE 事件內容。

開著一對一聊天視窗時，會請求顯示最長 60 秒的載入動畫，收到訊息即結束；它不是進度百分比，也不加快 AI。[LINE 載入動畫](https://developers.line.biz/en/docs/messaging-api/use-loading-indicator/)

## 9. 把範例改成自己的履歷

先完成模擬資料測試，再照 [履歷填寫指南](履歷填寫指南.md) 改寫。學生沒有工作經歷也能使用課程專題、社團、志工或實習。

唯一必要的正文邊界如下，兩個標記各佔一行：

```text
[[PUBLIC]]
## 個人介紹
這裡寫自己的介紹。
## 專案作品
這裡寫本人角色、做法與成果。
[[/PUBLIC]]
```

段落順序、標題名稱與欄位可以自由修改。Google 文件原生標題或 `## 標題` 有助分段；未填的 `[待填…]`／`[選填…]` 整行會被略過。公開區的嵌入圖片會在同步時辨識可見文字與標示數據，請用 previewImageText 核對。頁首頁尾、註腳、附件與外部連結內容不會自動讀入，需提供的網址請直接寫出完整文字。圖片操作見 [圖片知識庫](圖片知識庫.md)。

公開內容改完後執行 `syncKnowledgeBase`，不必重新部署。也可執行一次 `installHourlySync` 安裝每小時更新，時間不是精準整點；同步前機器人會提示更新中，避免引用舊資料。

### 維護待補充問題

查不到足夠資料時，原文件末尾會自動出現「待補充問題」表格，記錄原問題、原因、台北時間、次數與維護狀態。同題合併，主人填寫的註記會保留。

檢索未命中不代表文件一定缺漏，先核對現有內容。確認後把可公開答案補進公開區，重新同步；不要只把答案寫在表格裡。維護區不進入 RAG，也不會因新增問題讓索引失效。已處理列可以標記「已補充」「不公開」或刪除，保留外圍的 `[[UNANSWERED_QUESTIONS]]` 成對標記。

API 或 AI 產生錯誤不列為履歷缺漏；文件寫入失敗也不會聲稱記錄成功。記錄不附 LINE 使用者識別碼，但問題文字保存在主人的文件，所以不要公開分享整份來源文件。

圖片加入、換圖或刪除後，均需重新同步；checkSetup 的 publicImages 表示公開圖片數。圖片文字辨識、快取與錯誤排查詳見 [圖片知識庫](圖片知識庫.md)。

## 9-1. 開啟 Email 與 LINE 邀約通知

1. 在 Doc 公開正文的「公開聯絡方式」填入 `Email：你的實際信箱`，不要沿用範例地址，也不要只放在圖片裡。
2. GAS 點回程式碼.gs，選 `enableInvitationEmailNotifications` → 執行 → 依 Google 提示完成寄信授權。到 Doc 信箱確認「邀約通知啟用測試」郵件。新版 manifest 已包含 `script.send_mail`，不需要 Gmail 密碼或進階服務。
3. LINE Developers → 本機器人的 Messaging API 頻道 → **Basic settings → Your user ID**，複製 U 開頭共 33 字元的值。
4. GAS 專案設定 → 指令碼屬性 → 編輯 → 新增 `OWNER_LINE_USER_ID` 並貼上 → 儲存。同名屬性已存在就改原值；不是填官方帳號 @ID、Channel ID 或 Token。
5. 本人 LINE 加入自己的 bot 為好友且未封鎖。輸入「首頁」→「聯繫本人」→「留下邀約」，填完並確認送出，驗證 Email 與 LINE 各收到一份通知。
6. 平常直接看通知全文即可。需要整理記錄時才執行 `openInvitations`，從執行記錄開啟 20 分鐘有效的主人管理連結，標記已處理或刪除。

**授權只做一次；更改 userId 屬性不需重新部署。** 舊專案升級則必須先完成新增權限授權，再更新原正式部署。詳細畫面順序、測試標準、資料保存與寄信／推播失敗排查見 [聯繫與邀約通知](聯繫與邀約通知.md)。

## 10. 更新與停用

完整保留資料的順序見 [v1.6.2 升級指南](版本更新.md)。

**改程式：** 貼入同一版本的新 Code.gs 與 manifest、儲存、完成新增權限授權後，到「部署 → 管理部署」選原部署 → 編輯 → 版本選「新版本」→ 部署。只儲存程式不會更新版本化 Web App。

沿用原部署通常保持 URL；若另建新部署，需重新設定 `WEB_APP_URL`、執行 `showWebhookUrl` 並更新 LINE。

儲存程式與 manifest 後，先等儲存完成並重新整理 GAS，避免在尚未載入最新程式的編輯頁操作。完整程式與 manifest 必須來自同一個安裝包，單檔與分檔不要混貼。發布原部署的新版本後，先執行 `checkDeployment`；版本一致後，再看 `checkSetup.index`。`ready` 可直接測 LINE，只有 `needs_sync` 才需要重建索引。

**改名稱或金鑰：** 更新指令碼屬性，不必部署。更換入口密鑰執行 `rotateWebhookToken`，並立即更新 LINE 的完整網址。

**停止：** `BOT_ENABLED=false` 暫停問答，仍會回傳暫停提示；`removeHourlySync` 停止排程。完全停止接收可關閉 LINE Use webhook、封存 GAS 部署。文件保留於自己的 Drive，之後可自行刪除模擬文件與索引。

### v1.6.2 首頁、作品與通知

版本一致後，從舊版首次更新需執行一次 `syncKnowledgeBase` 補建代表主題。內容及辨識規則未變時沿用原向量與圖片快取。`checkSetup.quickReplies` 會列出 status 與 labels。LINE 的 Quick Reply 固定包含「我是誰」「快速一覽」，其餘最多四項依履歷生成互斥特色；一般共 3–6 項，資料不足時只保留兩個基本入口，不湊數。下一次公開內容變動並成功同步後才重建。

有作品圖片時，在 GAS 執行 `openImageReview`，開啟記錄中的完整管理連結，對照原圖校正後儲存並同步；可逐張選擇開放獨立副本，讓 LINE 顯示作品圖文卡片。管理連結僅供本人、20 分鐘有效。到 LINE 輸入「作品圖庫」，選作品後可追問「配色呢」，輸入「清除對話」重設。完整操作、儲存位置、權限與驗收見 [作品卡片與圖片校對](作品卡片與圖片校對.md)。

## 11. 常見錯誤

Email 與 LINE 邀約通知的權限、收件人、額度及結果狀態，另見 [通知排錯](聯繫與邀約通知.md#排錯)。

看 GAS 左側「執行項目」，找相同時間的 `doPost` 或管理函式記錄。回報錯誤碼即可，不要貼金鑰、完整 API 回應或含 key 的網址。

| 現象／錯誤碼 | 處理方式 |
| --- | --- |
| 沒有 initializeProject 選項 | 從左側「檔案」欄點回程式碼.gs／Code.gs，確認完整貼入程式並儲存；再找上方執行／偵錯附近的函式下拉選單 |
| 下載後不知道先開哪個檔案 | 全部解壓縮，用瀏覽器開啟和 README.md 同一層的 START_HERE.html；不需安裝 Node.js 或用其他軟體開 .gs |
| 複製按鈕被瀏覽器阻擋 | 使用頁面展開並選取的完整文字，按 Ctrl+C／⌘C 手動複製 |
| 授權時出現「Google 尚未驗證這個應用程式」 | 自己新建的專案都會出現；點「進階」→「前往 ResumeRAGbot（不安全）」 |
| 執行時出現權限不足、要求權限或 `STARTER_DOC_CREATE_FAILED` | 授權時可能漏勾項目；重新執行 initializeProject 並勾「選取全部」，必要時先到 [Google 帳戶第三方連線](https://myaccount.google.com/connections) 移除 ResumeRAGbot 再授權；仍失敗再核對帳號建立文件的權限 |
| AI Studio 顯示「You do not have access to Google AI Studio」 | 學校帳號被停用或未滿 18 歲；改用符合資格的個人帳號，或與老師確認 |
| 指令碼屬性無法輸入 | 先按「編輯指令碼屬性」；改完按「儲存指令碼屬性」 |
| 首頁名稱沒有改變 | 確認修改的是原本的 `DISPLAY_NAME`，沒有另外新增第二個同名屬性，並已儲存 |
| 部署對話框找不到「網頁應用程式」 | 點「選取類型」旁的齒輪圖示 |
| 「誰可以存取」沒有「所有人」 | 學校帳號政策限制；請管理員確認或改用個人帳號 |
| `MISSING_RESUME_DOC_ID` | 執行 initializeProject 自動建立，或設定自己的文件 ID |
| `OWNER_ONLY` | 使用擁有並執行專案的同一 Google 帳號，避免多帳號混用 |
| 文件權限錯誤 | 確認文件仍存在、只填 ID、執行帳號可編輯 |
| `DOC_TAB_NOT_FOUND` | 填實際分頁 ID 而非名稱；單份練習文件也可用 `*` |
| `NO_PUBLIC_CONTENT` | 核對公開標記與內容；所有行都是待填也會變成空白 |
| `UNCLOSED_MARKERS`／`INVALID_PUBLIC_MARKERS`／`INVALID_FEEDBACK_MARKERS` | 標記獨立成行、成對，不重複巢狀；不要刪掉維護區結束標記 |
| `QUICK_TOPICS_INVALID`／`QUICK_TOPICS_OVERLAP`／`QUICK_TOPICS_INCOMPLETE` | 自動主題分類格式、互斥或完整性未通過；重新同步，仍失敗時向老師回報錯誤碼 |
| 管理連結失效 | 在 GAS 執行 openImageReview，重新開啟完整連結；不要只複製問號前的網址 |
| `PORTFOLIO_IMAGE_NOT_READY`／`PORTFOLIO_PUBLISH_FAILED` | Drive 預覽或公開分享未成功，先確認學校允許公開分享，再稍後重試；文字搜尋仍可用 |
| `MISSING_GEMINI_API_KEY` | 在指令碼屬性填 GEMINI_API_KEY，再同步 |
| credentials 為 false，但已填值 | 檢查是否仍填 YOUR_／REPLACE_ 等範例文字、名稱是否正確、是否已按儲存 |
| document 為 ready、index 為 INDEX_INVALID／INDEX_MISSING | 文件可讀取，問題是索引；執行 syncKnowledgeBase 重建，保留原履歷 |
| testLineConnection 為 error | 看其 code／message；確認 Token 類型與頻道、網路及 LINE 服務狀態 |
| `INVALID_EMBEDDING_*` | 使用完整最新版程式，確認固定向量模型及 768 維；不要截斷向量，保留具體錯誤碼 |
| `GEMINI_HTTP_400`／`404` | 模型名稱、帳號可用性或請求設定問題；生成模型用 GEMINI_MODEL 設定 |
| `GEMINI_HTTP_401`／`403` | 金鑰、專案權限或服務存取問題，不是自訂問答額度 |

| `GEMINI_HTTP_429` | Google 專案配額或頻率達限；到 AI Studio 查原因，同專案換 Key 不代表配額重置 |
| `GEMINI_HTTP_5xx` | 供應商暫時失敗，稍後再試 |
| `SET_PUBLIC_WEB_APP_URL` | 填自己的正式 /exec 網址，不含 key，不使用 /dev |
| LINE Verify 401、403 或登入頁 | 確認 /exec、以我執行、所有人存取、授權完成；/dev 只供編輯者測試 |
| Verify 302 | 核對部署及權限；保留程式 HtmlService 回應，不改成會重新導向的 ContentService |
| Verify 成功但不回覆 | 檢查 Use webhook、完整 key、LINE Token、BOT_ENABLED 與 doPost 記錄 |
| 只收到「本帳號無法個別回覆」 | 官方帳號預設回應；核對 Webhook 並關閉重複自動回應 |
| `INVALID_WEBHOOK_TOKEN` | 執行 showWebhookUrl，將完整結果重新存到 LINE |
| `LINE_HTTP_401` | LINE Access Token 錯誤或失效，取得新值更新屬性 |
| `LINE_REPLY_400` | Reply Token 可能已用過、過期或格式問題；不要重播舊 replyToken |
| `LINE_LOADING_HTTP_*`／`LINE_LOADING_FAILED` | 動畫請求失敗，正式問答仍會繼續 |
| 履歷資料等待同步 | 先執行 checkDeployment；版本不同時先更新原部署，一致後再看 checkSetup.index，只有 needs_sync 才同步 |
| `DEPLOYMENT_VERSION_MISMATCH` | 編輯器與正式網址版本不同，現有索引已保留。核對安裝包版本、儲存並重整後，管理部署選原部署 → 新版本；再次 checkDeployment，不要反覆同步 |
| 未找到足夠資料 | 查看維護區原因；NO_RELEVANT_CHUNKS 是檢索未命中，INSUFFICIENT_EVIDENCE 是 AI 判定片段不足 |
| `ANSWER_INCOMPLETE`／`ANSWER_INVALID_FORMAT`／`ANSWER_INVALID_EVIDENCE`／`ANSWER_UNSUPPORTED_LINK` | Gemini 已回應，但 AI 回答未完成或沒通過引用檢查，不等於文件沒資料，也不是設定錯誤；LINE 訪客會看到「請稍後再試」，再問一次即可。testResumeAnswer 遇到這類情況會記為 `GEMINI_OK` 並列出未對上的引用，不再顯示紅色錯誤；若仍顯示紅色 `ANSWER_*` 錯誤，代表 GAS 裡還是舊版程式，請貼入新版 Code.gs |
| `FEEDBACK_WRITE_FAILED`／`FEEDBACK_BUSY` | 檢查文件編輯權限與維護標記，短暫鎖定可稍後再試 |
| `EVENT_BUSY`／`BATCH_DEADLINE` | 同事件尚在處理或同批處理過久，避免手動重播，稍後重新提問 |
| 更新程式但 LINE 沒改變 | 管理部署需發布新版本，只儲存原始碼不會生效 |

## 12. 費用、限制與驗收

同步使用向量 API，並在內容有變更時以生成 API 整理基本資料與最多四個適性特色；分類格式錯誤時最多重試一次。問答通常用一次問題向量與一次生成 API。內容沒變時不重建索引；選單、說明與隱私不呼叫 AI。沒有程式自訂問答上限，但 Gemini、LINE、GAS 各自有額度，不能保證免費，程式也不會替你開通付款。[Gemini 配額](https://ai.google.dev/gemini-api/docs/rate-limits) · [Gemini 定價](https://ai.google.dev/gemini-api/docs/pricing) · [GAS 配額](https://developers.google.com/apps-script/guides/services/quotas)

公開文字會交給 Gemini 建立向量；提問時傳送問題與檢索片段。使用免費額度時，Google 可能用送出的內容改善服務，並由人員審閱，條款要求不要送出敏感、機密或個人資料。公開區只放願意公開的內容，不要寫電話、住址或證件號碼；先用虛構資料練習。[API 條款](https://ai.google.dev/gemini-api/terms)

純 GAS 無法驗證 LINE 簽章，秘密網址不能證明請求一定來自 LINE。同步等待 AI 可能超過 Reply Token 時效，不會自動 Push 補答。支援一對一文字問答與作品卡片，短期對話記憶約 10 分鐘（快取可能提早失效），來源最多約 60,000 字／100 片段。[LINE 簽章驗證](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/) · [LINE 回覆介面](https://developers.line.biz/en/reference/messaging-api/#send-reply-message)
