# v3 情境式個人介紹候選版

本分支版本為 `3.0.0-rc.1`，供老師審查。老師的 v2.0.0 正式安裝包仍是獨立版本。提交者回報已將候選程式更新到自己的 GAS，並從 LINE 操作實測；目前未提供部署版本輸出、逐項測試紀錄或截圖，因此這是提交者回報，並非本機測試可獨立證明的結果。

## 使用流程

在首頁第三張「履歷導覽」點「情境式個人介紹」，選「人資面試」「專案合作」或「一般認識」。Bot 從已同步的公開履歷索引選取相關片段，產生簡短介紹、來源區段和三個固定延伸問題。訪客可點問題，也可直接輸入其他問題；輸入「切換情境」可再選，輸入「取消介紹」或「首頁」會清除情境。介紹內容只依實際公開履歷生成，沒有明載興趣時會說資料不足。

## 實作與檔案

- `gas/ContextIntro.gs`：三種情境、公開片段挑選、選單、介紹與建議問題。
- `gas/Webhook.gs`：在邀約處理之後接入新操作，維持事件去重、回覆成功後才儲存短期狀態。
- `gas/Conversation.gs`、`gas/Chat.gs`：在原本按訪客雜湊的 10 分鐘快取中增存情境。情境只影響自由問答的重點與語氣，不限制可檢索的公開內容。
- `gas/Gemini.gs`：沿用向量檢索、原文引用驗證、生成前後公開文件指紋檢查；介紹與固定建議問題資料不足時不寫入待補充區。
- `gas/Line.gs`：首頁入口及既有 Flex、Quick Reply 組件。
- `test/context-intro.test.mjs`：使用虛構履歷與 Mock API 測試情境、來源、狀態及原功能共存。

不會因選擇情境而重新 OCR 或重建完整索引。工作／專案／興趣的候選片段以明確文字標記辨識；若履歷以隱晦措辭記載相關內容，可能顯示資料不足。Gemini 回答仍有誤判可能，引用驗證能確認來源片段存在，不能替代本人逐句審核。GAS 快取可能提前失效，舊延伸問題按鈕會要求重新選情境。

## 本機測試

在專案根目錄執行：

```sh
npm ci
npm run check
npm test
npm run bundle
npm run check:bundle
npm run check:docs
```

`npm run bundle` 會把分檔產生為 `dist/Code.gs`，並更新 `START_HERE.html`。Mock 測試不會使用真實 API Key，也不會發 LINE 訊息。

## 部署到自己的測試 GAS

先備份目前正式 v2 GAS 專案或另建測試 GAS 專案，核對目的地 Script ID、Doc 與 LINE 頻道。不要把他人的 ID 或金鑰放進 Git。

**單檔方式：**在自己的測試 GAS 中，以 `dist/Code.gs` 更新程式碼檔；核對 `gas/appsscript.json` 與 GAS manifest，再儲存。完成授權與設定後，先建立新的 Web App 部署版本，核對 `/exec` 與 `checkDeployment` 的版本均為 `3.0.0-rc.1`，再視需要執行 `syncKnowledgeBase`、`checkSetup`。更新程式碼本身不會更新既有版本化部署。

**clasp 方式：**依 [開發指南](開發指南.md) 安裝並登入 clasp，只在自己的測試 GAS 專案根目錄設定 `.clasp.json`（`rootDir` 為 `gas`）。核對 Script ID 後執行 `clasp push`，再到 GAS「管理部署」建立新版本。`clasp push` 不會自動更新 LINE 使用的部署。

## LINE 手動驗收

1. 從 LINE 開首頁，檢查三張卡、快速主題、作品、聯繫和邀約仍可用。
2. 點情境入口，依序選三種情境；核對實際 Doc 中的原文與來源。特別測試沒有興趣欄位時的資料不足回覆。
3. 各點一個延伸問題，再自行輸入跨情境問題；確認可正常問答。
4. 切換情境、回首頁、清除對話；用兩個 LINE 帳號測試狀態隔離，並點舊訊息中的按鈕。
5. 修改測試 Doc 的公開內容但尚未同步時，確認 Bot 拒絕舊索引；同步後重新驗收。
6. 檢查 GAS 執行記錄與實際 LINE 回覆，確認沒有私人區或待補充內容、沒有真實金鑰暴露。

以上真實 GAS 與 LINE 項目需由擁有帳號的人操作。提交者回報已完成 GAS 更新與 LINE 實測；逐項結果、測試帳號數及正式部署版本仍待補充。本機 Mock 測試與真實 LINE 驗收分開記錄。
