# 人資三題與圖片驗證

## 功能來源與流程

人資三題與需求熱圖改編自 [老師 PR #2](https://github.com/canlgz/ResumeRAGbot/pull/2) 的公開 MIT 程式，來源 commit 為 aed4bdfc08ea76d083a6984b82de8041832fe113。新增的 `gas/Hr.gs` 保留來源註記；原有獨立職缺對照仍可使用。

LINE 底部 Quick Reply 的第三個按鈕為「人資」，首頁第三張卡片另有「人資三題與熱圖」。依序收集主要工作職稱、工作技能與深度、具體工作／專案經驗。第三題可略過。建議以「人資回答」開頭換行填入，草稿提早失效時可提示重新開始，避免需求被當成一般履歷問題。

前兩題提供即時文件內容檢核，第三題產生文字分析、資料來源泡泡與「需求 × 技能／經歷／作品／成果」熱圖，提供邀約、聯繫與重新評量入口。熱圖整理的是公開文件證據強度，不能當作本人能力的確定結論或錄取建議。履歷未寫不代表本人不會。

整合修改包含：拒絕未知來源 ID、熱圖欄位及列數驗證、生成前後來源 fingerprint 核對、第三題 API 失敗保留草稿、切換職缺對照或聯繫時清除不同流程草稿。需求不寫入履歷、索引或待補充問題。草稿按訪客雜湊隔離，約三十分鐘過期。

## 檢查與限制

本機 162 項測試通過，含人資三題流程、來源、熱圖輸出、訪客隔離、取消、API 失敗重試、生成期間來源更新與流程切換。程式、產生檔及文件檢查通過。

2026-11-04 測試 GAS 已更新為部署快照第 3 版，沿用原測試 webhook。使用者提供上午 11:27 的 LINE 截圖，確認底部「人資」按鈕與熱圖訊息已顯示；可見經驗列、四個強度儲存格與邀約／重新評量／聯繫按鈕。截圖只顯示熱圖下半部，未據此宣稱每個矩陣格的評級正確。

沿用老師的主觀文件評級與模型摘要，來源 ID 合法不代表每一句摘要已逐字核對。模型可能誤判，需要人工閱讀原履歷確認。最後一步需多次向量搜尋與生成，仍可能超過 LINE 回覆時效。全域鎖會限制同時操作；未做多人壓力測試。尚未完整處理所有 LINE 回覆失敗後重送事件的步驟重播。

## 圖片 RAG 測試素材

沿用 v2 的 `gas/Images.gs` 圖片文字與視覺觀察擷取流程。僅在模擬履歷公開區放入自製虛構測試圖片，沒有放入真實證件、私人照片或真實履歷。

測試圖有代碼 DEMO-IMG-7319、INPUT／CHECK／REPORT 三個彩色方塊，以及 Validation sample count: 37。代碼與數字只存在圖片，未抄入履歷正文；用於確認答案來自圖片辨識與檢索。原履歷文件維持私有，圖片預覽是否公開另外控制。

預期驗收：LINE 詢問「圖片 RAG 測試作品的測試代碼、樣本數與三個區塊文字是什麼？」時，回覆代碼、37、三個區塊與圖片來源。同步第一次在主題分類階段出現 QUICK_TOPICS_INCOMPLETE，重試後成功（SYNC_OK，13 個片段、1 張圖片）。

使用者上午 11:27 截圖確認 LINE 回答代碼 DEMO-IMG-7319、樣本數 37，描述三個彩色圓角方塊，且附「圖片 RAG 測試作品（虛構測試素材）｜圖片 1（圖片辨識）」來源。圖片辨識與檢索已實際運作；但此次回答漏列 INPUT／CHECK／REPORT，尚待針對三個英文區塊補問。`previewImageText` 尚未另外執行，不列為通過。
