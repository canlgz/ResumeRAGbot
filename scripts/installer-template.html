RESUMERAGBOT · 學生安裝包 __VERSION__

把自己的履歷變成 LINE 機器人

先用完整模擬履歷完成測試，再換成自己的資料。照順序完成下列步驟，每一階段都有完成判斷。

請先將 ZIP 全部解壓縮，再用電腦瀏覽器開啟這個 START_HERE.html（它和 README.md 放在同一個資料夾）。此頁已內含要複製的程式，無須安裝 Node.js 或 Git。

開始前先確認帳號：建議使用年滿 18 歲的個人 Gmail，從頭到尾用同一個 Google 帳號。Gemini API 條款要求使用者年滿 18 歲；學校 Google 帳號（Workspace for Education）未滿 18 歲不能使用 AI Studio，學校帳號也可能無法把網頁應用程式開放給「所有人」。不符合時請先告知老師。另需一個能登入的 LINE 帳號。

金鑰只填入自己的 GAS「指令碼屬性」。此頁不要求輸入或保存金鑰。Google 授權、LINE 頻道與 API 配額使用自己的帳號。

  2. 點編輯器上方的標題「未命名的專案」，改成 ResumeRAGbot，按「重新命名」。
  3. 左側「檔案」欄點選 程式碼.gs（英文介面為 Code.gs），在中央程式區按 Ctrl+A（Mac：⌘A）全選，刪除預設的 myFunction。
  4. 按下方「複製完整程式」，回到編輯器貼上（Ctrl+V／⌘V），再按上方磁碟圖示「儲存專案」或 Ctrl+S（⌘S）。

    步驟 3
初始化，取得自己的履歷文件

    
    
      
  1. 確認程式與 manifest 都已儲存後，重新整理 GAS 分頁；再從左側「檔案」欄點回程式碼.gs／Code.gs，確認中央顯示程式碼，而非 appsscript.json 的 JSON。
    2. 
      
  2. 在編輯器上方、「執行／偵錯」附近的函式下拉選單，選擇 initializeProject，按「執行」。
    3. 
      
  3. 跳出「需要授權」時按「審查權限」，選擇剛才的 Google 帳號。
    4. 
      
  4. 若出現「Google 尚未驗證這個應用程式」：這是自己剛建立的專案，點左下「進階」，再點「前往 ResumeRAGbot（不安全）」。
    5. 
      
  5. 權限清單請勾選「選取全部」（或把每一項都勾起來），再按「繼續」。漏勾任何一項，之後建立文件、同步或連 LINE 時會出現權限錯誤。
    6. 
      
  6. 編輯器下方會打開「執行記錄」。找到「履歷文件：」那一行，複製後面的網址，貼到瀏覽器新分頁開啟。
    7. 
    

    
記錄前面是一長串 JSON，先看最後幾行的「履歷文件：」及「下一步 1、2…」即可。如果看不到 initializeProject，請先確認已點回 .gs 檔案、完整貼上程式並儲存，等待編輯器完成載入後再打開函式選單。漏勾權限時，再執行一次 initializeProject，Google 會重新詢問；若沒有再詢問，到 Google 帳戶的第三方連線 移除 ResumeRAGbot 的存取權後重新執行。

    
會自動建立含填寫指引、技能與三個專案的模擬履歷。重複初始化會沿用原文件。尚未填 API Key 時，檢查顯示 API 欄位為 false 是正常的。

    
完成判斷：自己的 Drive 出現「ResumeRAGbot｜模擬履歷（請修改）」，記錄中 document 是 ready。左側齒輪「專案設定」最下方的「指令碼屬性」已自動出現 RESUME_DOC_ID、DOC_TAB_IDS、WEBHOOK_TOKEN、DISPLAY_NAME、GEMINI_MODEL、BOT_ENABLED 六項，不要刪除。不要手動執行 doPost。

  


  

    步驟 4
設定自己的 LINE 與 Gemini

    
4-1 建立 LINE 官方帳號並取得 Token

    
    
      
  1. 開啟「LINE 帳號後台」（LINE Official Account Manager），用自己的 LINE 帳號登入；第一次會要求註冊 LINE Business ID。
    2. 
      
  2. 按「建立帳號」，依表單填寫帳號名稱（例如「王同學履歷」）、業種等必填欄位後送出。一般帳號即可，不需申請認證。
    3. 
      
  3. 進入該帳號的管理頁，按右上「設定」，左側選「Messaging API」，按「啟用 Messaging API」。
    4. 
      
  4. 第一次會要求登錄開發者資訊：輸入姓名與 Email、同意條款。接著選擇 Provider：沒有的話建立新的 Provider，名稱可用自己的名字（設定後無法更換）。若出現隱私權政策／服務條款網址欄位，可留空，按確定。
    5. 
      
  5. 開啟「LINE Developers」，用同一個 LINE 帳號登入，點剛才的 Provider，再點和官方帳號同名、類型為 Messaging API 的頻道。
    6. 
      
  6. 點上方「Messaging API」分頁，捲到最下方「Channel access token (long-lived)」，按「Issue」，再按旁邊的複製圖示。不要複製 Basic settings 分頁的 Channel secret。
    7. 
    

    
4-2 建立 Gemini API Key

    
    
      
  1. 開啟「AI Studio API Keys」，用同一個 Google 帳號登入；第一次需同意服務條款。
    2. 
      
  2. 按「建立 API 金鑰／Create API key」。若要求選擇 Google Cloud 專案，選 AI Studio 自動建立的預設專案，或依畫面建立新專案。
    3. 
      
  3. 複製產生的金鑰。看到「You do not have access to Google AI Studio」表示帳號被學校限制或未滿 18 歲，請改用符合資格的個人帳號或告知老師。
    4. 
    

    
LINE 帳號後台LINE DevelopersAI Studio API Keys

    
4-3 填入 GAS 指令碼屬性

    
    
      
  1. 回到 GAS，點左側齒輪「專案設定」，捲到最下方「指令碼屬性」，按「編輯指令碼屬性」。
    2. 
      
  2. 找到初始化已建立的 DISPLAY_NAME，直接把值「個人履歷」改成自己的名稱。不要再新增第二個 DISPLAY_NAME。
    3. 
      
  3. 按「新增指令碼屬性」兩次，分別新增 LINE_CHANNEL_ACCESS_TOKEN 與 GEMINI_API_KEY：左欄填名稱（可按下表按鈕複製），右欄貼值，前後不要有空白或引號。
    4. 
      
  4. 按「儲存指令碼屬性」。沒有按儲存，程式讀不到新值。
    5.

完成判斷：回到編輯器，依序執行 testLineConnection → checkSetup。testLineConnection 的 status 是 ready、botName 是自己的官方帳號；checkSetup 的 credentials 三項為 true。這兩個檢查都不發 LINE 訊息。

  


  

    步驟 5
同步履歷並確認 AI 能回答

    
依序在函式下拉選單選擇並執行 syncKnowledgeBase → checkSetup → testResumeAnswer。這裡會使用自己的 Gemini API 配額，同時依履歷產生 3–6 個代表關鍵主題，先保留模擬資料測試即可。相同已同步內容之後沿用同一份 Quick Reply，不會每次聊天重新分類。

    
完成判斷：document 與 index 都是 ready，testResumeAnswer 沒有出現紅色錯誤，再執行 checkSetup 時 answerTest 為 OK 或 GEMINI_OK。OK 會顯示回答與來源，可對照文件；GEMINI_OK 代表 Gemini 已正常回應、只是這次 AI 回答沒通過來源檢查，屬偶發狀況，不是設定錯誤，直接進行下一步。出現紅色錯誤時，先照記錄的說明與 checkSetup 的「下一步」處理，不必急著部署。

  


  

    步驟 6
部署為所有人可存取的 Web App

    
    
      
  1. 按編輯器右上藍色「部署」→「新增部署作業」。
    2. 
      
  2. 對話框左上「選取類型」旁有齒輪圖示，點齒輪後選「網頁應用程式」。
    3. 
      
  3. 說明填 ResumeRAGbot v__VERSION__。「執行身分」選「我（自己的 Gmail）」；「誰可以存取」選「所有人」，不是「任何擁有 Google 帳戶的使用者」。
    4. 
      
  4. 按「部署」。若再次要求授權，照步驟 3 完成並勾選全部權限。
    5. 
      
  5. 複製「網頁應用程式」下方、結尾為 /exec 的網址（不是上方的「部署作業 ID」），按「完成」。
    6. 
      
  6. 到「專案設定 → 指令碼屬性 → 編輯指令碼屬性 → 新增指令碼屬性」，名稱填 ，值貼上網址，按「儲存指令碼屬性」。
    7. 
      
  7. 回到程式碼.gs，執行 checkDeployment。確認 status=ready，editorVersion 與 webAppVersion 都是 __VERSION__，再繼續連接 LINE。
    8. 
    

    
請用自己部署結果的網址，不能把 /dev 的結尾直接改寫成 /exec。

    
完成判斷：checkDeployment 的兩個版本都與本安裝包 __VERSION__ 相同。也可用無痕視窗開啟不含 key 的 /exec 核對。GAS 的「版本 1、版本 2…」是快照編號，並不是本安裝包的版本號；不能只看快照編號較大就認為程式較新。

  


  

    步驟 7
連接 LINE Webhook

    
    
      
  1. GAS 函式選單選 showWebhookUrl 並執行，複製執行記錄中含 ?key= 的完整網址。
    2. 
      
  2. 開啟 LINE Developers → 自己的頻道 →「Messaging API」分頁 →「Webhook settings」，在 Webhook URL 旁按「Edit」，貼上網址後按「Update」。
    3. 
      
  3. 按「Verify」看到 Success 後，開啟下方「Use webhook」開關。
    4. 
      
  4. 同一分頁的「Auto-reply messages」或「Greeting messages」旁按「Edit」，會開啟 LINE 帳號後台「設定 → 回應設定」：關閉「自動回應訊息」與「加入好友的歡迎訊息」，並確認「Webhook」為開啟。
    5. 
      
  5. 用手機 LINE 掃描「Messaging API」分頁上方的 QR code，加入自己的官方帳號為好友。
    6. 
    

    
完成判斷：加入好友後收到履歷首頁，或傳「選單」能收到首頁。Verify 成功只能證明網址有回應，仍須這一步確認真正收送訊息。

  


  

    步驟 8
測試回答，再改成自己的履歷

    
先問「報表自動化省了多少時間？」並對照模擬履歷，再問一題文件沒有的問題，確認原文件出現「待補充問題」。

    
將範例改成自己的真實資料時，只要保留獨立成行的 [[PUBLIC]] 與 [[/PUBLIC]]，中間可自由撰寫。沒有工作經驗可用課程專題、社團或實習，詳細範例見填寫指南。

    
也可以插入作品圖片：把介面、海報或照片放在公開區，執行 syncKnowledgeBase 後，用 previewImageText 分別核對圖片文字與畫面描述，再到 LINE 提問。辨識結果存在自己的 Drive「LINE 履歷 RAG 索引.json」，不會自動寫回履歷正文；圖片沒變且有快取時會沿用結果。

    
使用 Gemini 免費額度時，送出的內容可能被 Google 用於改善服務並由人員審閱。公開區只放願意公開的內容，不要寫電話、住址、證件號碼等個人敏感資料。

    
完成判斷：改完公開內容後執行 syncKnowledgeBase，再提問驗證新資料。只改文件不用重新部署程式；改程式則要發布新版本。

  

  

    步驟 9 · 有作品圖片時
校對辨識、開放作品卡片並測試追問

    
    
      
  1. 在履歷公開區插入兩張不同用途的作品圖片，各用自然標題寫上作品名稱，執行 syncKnowledgeBase。
    2. 
      
  2. 回到 GAS「程式碼.gs／Code.gs」，選 openImageReview 並執行；從執行記錄複製完整管理連結（包含 # 後內容），在新分頁開啟。
    3. 
      
  3. 對照原圖，修改「圖片文字」或「畫面描述」，按「儲存校對並同步」。校對資料另外儲存，不會新增到原 Google 文件。
    4. 
      
  4. 逐張勾選公開副本的同意項目，按「開放作品預覽」。只有選中圖片的獨立副本開放持連結者讀取，原文件、索引及校對管理檔不必公開。
    5. 
      
  5. 先按「測試主題問答」，確認每一類都有答案與來源（使用 Gemini API、不傳 LINE 訊息）；再按「檢查 LINE 作品卡片」驗證格式。最後到 LINE 輸入「作品圖庫」，點「問這件作品」，接著問「這張配色呢？」。
    6. 
      
  6. 約 10 分鐘內可沿用作品指向；輸入「清除對話」重新開始。若出現額度錯誤，依訊息區分 Google API 配額與安裝問題。
    7. 
    

    
管理連結 20 分鐘有效，僅供本人使用，不轉傳或交作業。圖片可隨時撤回公開預覽，但已傳送、下載或快取的圖片無法收回。學校帳號若禁止公開分享，仍可搜尋圖片內容，作品卡片則無法開放。

    
完成判斷：LINE 能顯示作品圖文卡片、接續回答同一件作品；Quick Reply 為 3–6 個實際履歷主題且不重複，不混入操作指令。內容未改的再次同步，主題不變。內容不足三組時不會編造選單，仍能直接提問。

  

  

    日後更新
更新程式時，先對齊版本再同步

    
    
      
  1. 只使用同一個安裝包的完整程式與 manifest；保留原指令碼屬性及履歷。不要把新版、舊版或單檔、分檔混貼。
    2. 
      
  2. 儲存完成後，關閉同專案其他舊編輯分頁，重新整理目前分頁。執行 checkSetup，確認 version 與安裝包相同。
    3. 
      
  3. 到「部署 → 管理部署」編輯原部署，版本選「新版本」並部署；通常沿用原網址。
    4. 
      
  4. 執行 checkDeployment。兩個版本相同、status=ready 後，再看 checkSetup.index：ready 可直接測 LINE；只有 needs_sync 才重跑 syncKnowledgeBase。
    5. 
    

    
從 v1.2.x 更新到本版，版本一致後執行一次 syncKnowledgeBase 補建代表主題選單。原履歷及辨識規則未變時沿用向量和圖片快取。之後看 checkSetup.quickReplies 的 status 與 labels 確認分類。

    
若顯示 DEPLOYMENT_VERSION_MISMATCH，程式會保留現有索引。請先修正版本，不要一直重跑同步。若找不到 checkDeployment，代表貼入的程式仍是舊版；若檢查回報無法連線，需核對公開權限與網址，這不等於版本不同。
