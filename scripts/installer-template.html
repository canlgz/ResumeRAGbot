RESUMERAGBOT · 學生安裝包 __VERSION__

把自己的履歷變成 LINE 機器人

先用完整模擬履歷完成測試，再換成自己的資料。照順序完成下列步驟，每一階段都有完成判斷。

請先將 ZIP 全部解壓縮，再用電腦瀏覽器開啟這個 START_HERE.html。此頁已內含要複製的程式，無須安裝 Node.js 或 Git。

金鑰只填入自己的 GAS「指令碼屬性」。此頁不要求輸入或保存金鑰。Google 授權、LINE 頻道與 API 配額使用自己的帳號。

步驟 1

建立 GAS 專案，貼入程式

開啟自己的 Google Apps Script，新增專案並命名 ResumeRAGbot。左側檔案欄點選 Code.gs（也可能顯示「程式碼.gs」），刪除預設的 myFunction，貼入下方複製的完整程式並儲存。

開啟 Google Apps Script
查看程式文字；若不能自動複製，也可手動複製

    
完成判斷：儲存後，上方函式選單可以找到 initializeProject。單檔已包含全部程式，不要再加貼 gas/ 的分檔。

  


  

    步驟 2
設定 manifest

    
左側齒輪「專案設定」勾選「在編輯器中顯示 appsscript.json」。回到編輯器，打開 appsscript.json，將內容全部換成下方 JSON 並儲存。

    

    
查看 manifest

    
完成判斷：Code.gs 放程式，appsscript.json 放 JSON。儲存後，請從左側檔案欄點回「程式碼.gs／Code.gs」，再進行步驟 3。

  2. 在編輯器上方、「執行／偵錯」附近的函式下拉選單，選擇 initializeProject。

會自動建立含填寫指引、技能與三個專案的模擬履歷。重複初始化會沿用原文件。尚未填 API Key 時，檢查顯示 API 欄位為 false 是正常的。

    
完成判斷：自己的 Drive 出現「ResumeRAGbot｜模擬履歷（請修改）」，記錄中 document 是 ready。不要手動執行 doPost。

  


  

    步驟 4
設定自己的 LINE 與 Gemini

    
到 LINE Official Account Manager 建立官方帳號並啟用 Messaging API，再到 LINE Developers 的對應頻道取得 Channel access token (long-lived)。到 Google AI Studio 建立自己的 API Key。

    
在 GAS「專案設定 → 指令碼屬性」新增下表內容，按儲存。點屬性名稱可複製名稱，值填自己的資料。

    
屬性名稱值

      
LINE Channel access token；不是 Channel secret。

      
自己的 Google AI Studio API Key。

      
例如「王同學｜履歷測試」。

    

    
LINE 帳號後台LINE DevelopersAI Studio API Keys

    
完成判斷：執行 checkSetup，credentials 三項為 true；再執行 testLineConnection，狀態是 ready，帳號名稱是自己的官方帳號。此檢查不發訊息。

  


  

    步驟 5
同步履歷並確認 AI 能回答

    
依序執行 syncKnowledgeBase → checkSetup → testResumeAnswer。這裡會使用自己的 Gemini API 配額，先保留模擬資料測試即可。

    
完成判斷：document 與 index 都是 ready，testResumeAnswer 能根據文件回答並附來源。若有錯誤，先按照 checkSetup 的「下一步」處理，不必急著部署。

  


  

    步驟 6
部署為所有人可存取的 Web App

    
右上「部署 → 新增部署作業 → 網頁應用程式」，執行身分選「我」，存取選「所有人」。複製部署結果的網頁應用程式網址，結尾應為 /exec。

    
將該網址存入指令碼屬性 。請用自己部署結果的網址，不能把 /dev 的結尾直接改寫。

    
完成判斷：用無痕視窗開啟不含 key 的 /exec，可看到「LINE 履歷助理已部署」與本安裝包版本號。若版本不同，請在管理部署發布新版本。

  


  

    步驟 7
連接 LINE Webhook

    
在 GAS 執行 showWebhookUrl，把執行記錄中含 ?key= 的完整網址存入 LINE Developers → Messaging API → Webhook URL，按 Verify 並開啟 Use webhook。到官方帳號後台關閉重複的自動回應與歡迎訊息。

    
完成判斷：加入自己的官方帳號並傳「選單」，能收到履歷首頁。Verify 成功只能證明網址有回應，仍須這一步確認真正收送訊息。

  


  

    步驟 8
測試回答，再改成自己的履歷

    
先問「報表自動化省了多少時間？」並對照模擬履歷，再問一題文件沒有的問題，確認原文件出現「待補充問題」。

    
將範例改成自己的真實資料時，只要保留獨立成行的 [[PUBLIC]] 與 [[/PUBLIC]]，中間可自由撰寫。沒有工作經驗可用課程專題、社團或實習，詳細範例見填寫指南。

    
完成判斷：改完公開內容後執行 syncKnowledgeBase，再提問驗證新資料。只改文件不用重新部署程式；改程式則要發布新版本。
